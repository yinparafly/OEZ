ArduPilot SITL 连接问题汇总 — 寻求帮助
========================================
日期: 2026-07-04
环境: Windows 10/11 + WSL2 Ubuntu 22.04 + pymavlink 2.4.49

========================================
问题一: SITL 用 TCP 模式启动后立即崩溃
========================================

现象:
  启动命令:
    arduplane --model plane --serial0 tcp:5760 --home CMAC

  日志输出:
    bind port 5760 for SERIAL0
    SERIAL0 on TCP port 5760
    Waiting for internal clock bits to be set (current=0x00)
    (进程退出, 端口 5760 无进程监听)

  pymavlink 连接时:
    ConnectionRefusedError: [WinError 10061] 由于目标计算机积极拒绝，无法连接。

分析:
  - "clock bits" 消息来自 SIM_LP5562.cpp (LED 驱动仿真), 不是主仿真循环
  - 进程确实启动并绑定了端口, 但几秒后自行退出
  - 猜测: TCP 模式下需要外部系统(如 MAVProxy)立即连接并握手, 否则超时退出
  - sim_vehicle.py 默认使用 UDP 模式 (udpclient:127.0.0.1:5760), 不是 TCP


========================================
问题二: SITL 用 UDP 模式启动成功, 但 pymavlink 只收到心跳
========================================

现象:
  启动命令:
    arduplane -I0 --model plane --speedup 1 --serial0 udpclient:127.0.0.1:5760 --home CMAC

  进程存活 (PID 状态 Sl+), 不崩溃

  pymavlink 连接:
    master = mavutil.mavlink_connection('udp:127.0.0.1:5760', source_system=255)
    master.wait_heartbeat(timeout=15)
    → 收到心跳! System=0, Type=1(FixedWing), Mode=UNKNOWN

    master.mav.request_data_stream_send(...)
    → 10 秒内收到 0 条数据消息 (空速、姿态、GPS 等全部没有)

  关键:
    - 心跳收到 = UDP 通信链路本身是通的
    - System=0 (应该是 1) = 自动驾驶仪可能未完成初始化
    - Mode=UNKNOWN = 飞行模式未识别
    - 无遥测数据 = 仿真步进可能卡住


========================================
问题三: WSL2 TCP 端口从 Windows 访问被拒绝
========================================

现象:
  SITL 在 WSL 内部绑定 TCP 5760:
    bind port 5760 for SERIAL0
    SERIAL0 on TCP port 5760
    Waiting for connection ....

  从 Windows pymavlink 连接:
    mavutil.mavlink_connection('tcp:127.0.0.1:5760')
    → ConnectionRefusedError: [WinError 10061]

    mavutil.mavlink_connection('tcp:172.30.31.168:5760')  # WSL IP
    → 同样 ConnectionRefusedError

  WSL 配置 (.wslconfig):
    [wsl2]
    memory=4GB
    processors=4
    swap=4GB
    localhostForwarding=true

  文档说 localhostForwarding=true 应该让 Windows 通过 localhost 访问 WSL 服务,
  但实际上不行。

  注意: 之前通过 COM15/COM16 (USB 串口) 连接真实硬件 Nora 飞控是正常的,
  pymavlink 连接 COM 口没有问题。问题只出在 WSL TCP 连接上。


========================================
我们的尝试和已知信息
========================================

1. 直接用 arduplane 二进制启动 (不通过 sim_vehicle.py)
   - TCP 模式: 崩溃
   - UDP 模式: 进程存活但无数据流

2. WSL 网络:
   - localhostForwarding=true 已配置
   - WSL IP: 172.30.31.168
   - Windows 无法连接 WSL 的 TCP 端口 (5760/5762)
   - WSL 内部也没装 nc/netstat, 无法从内部验证

3. sim_vehicle.py:
   - 每次运行会重新 waf configure, 耗时长
   - 默认用 UDP: --serial0 udpclient:127.0.0.1:5760
   - 默认启动 MAVProxy 连接 SITL

4. pymavlink UDP 连接:
   - udp:127.0.0.1:5760 能收到心跳
   - 但 0 条遥测数据
   - request_data_stream_send 无响应

5. 之前的成功经验:
   - COM15/COM16 USB 串口连接真实 Nora 飞控: 一切正常
   - 参数读写、遥测、航点上传全部验证通过
   - 问题仅限于 SITL 模拟器连接
