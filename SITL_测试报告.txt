========================================
关键发现
========================================

1. 方案4 (默认配置) 没有 clock bits 问题
   日志: "Waiting for connection ...." (正确状态)
   但 TCP 从 Windows 连不上 WSL (ConnectionRefused)

2. 方案5 (sim_vehicle.py --udp) 也没有 clock bits
   它设置 --serial0 udpclient:127.0.0.1:5760
   pymavlink 能收到心跳, 但 System=0, 无遥测数据

3. clock bits 问题的规律:
   - 只要显式指定 --serial0 (无论 tcp 还是 udpclient), 就出现
   - 不指定 --serial0 (用默认值), 就不出现
   - 这说明 clock bits 可能与 serial 配置的初始化顺序有关

4. System=0 的含义:
   - ArduPilot 固件还没完成初始化
   - 心跳能收到是因为固件主循环直接发送
   - 但遥测数据需要仿真步进推进, 而仿真被 clock bits 卡住

========================================
Windows 到 WSL 的网络连通性
========================================

TCP 连接:
  tcp:127.0.0.1:5760       → ConnectionRefused
  tcp:172.30.31.168:5760    → ConnectionRefused (WSL IP)
  tcp:172.30.16.1:5760      → ConnectionRefused (Windows IP)

UDP 连接:
  udp:127.0.0.1:5760       → 收到心跳 (System=0)
  udp:127.0.0.1:14550      → 收到心跳 (System=0)
  udp:0.0.0.0:14550        → 收到心跳 (System=0)

结论: UDP 通信链路本身是通的, 但飞控未完成初始化

========================================
问题根因分析
========================================

问题 A: TCP 连接全部被拒绝
  原因: WSL2 NAT 模式下, Windows 无法通过 TCP 连接 WSL 内部端口
  证据: localhostForwarding=true 已配置但仍失败
  可能解法: 需要 mirrored 网络模式或 netsh portproxy

问题 B: UDP 收到心跳但无遥测
  原因: "clock bits" 阻止了仿真步进
  证据: 所有显式指定 --serial0 的方案都有 clock bits
  影响: 仿真不推进 → 无遥测数据产生 → request_data_stream 无效

问题 C: clock bits 的来源
  代码位置: SIM_LP5562.cpp:119
  含义: LED 驱动仿真等待内部时钟配置
  规律: 只在显式指定 serial0 时出现
