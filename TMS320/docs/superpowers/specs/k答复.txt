## 1. 问题一：eQEP 捕获单元（QCAP）确实没有中断

**结论：完全正确。**

从 C2000Ware 5.04 的 `hw_eqep.h`、`eqep.h` 以及历代 TRM（F28x、F2837x、F28P55x 等）来看：

- QFLG 只有 13 个标志：INT、PCE、PHE、QDC、WTO、PCU、PCO、PCR、PCM、SEL、IEL、UTO、QMAE。
- **没有任何“捕获周期就绪 / 捕获事件”标志**。
- QCAPCTL 只有 UPPS、CCPS、CEN，没有中断使能位。
- TI 官方示例（eqep_ex4_freq_cal_interrupt）明确用 **Unit Timeout (UTO)** 中断 + 读 QPOSCNT/QCPRD，捕获单元只做硬件锁存。

QCAP 的设计目的是**低速测速辅助**（在单位位置事件间测量时间），不是“每个边沿通知 CPU”。因此原计划里“每个 AB 边沿触发捕获中断写事件点”在硬件上**不可行**。

## 2. 问题二：枚举名与分辨率切换

**大部分正确，有一处需要再确认。**

| 原假设 | 实际 | 说明 |
|--------|------|------|
| `EQEP_INT_CAPTURE_PERIOD` | 不存在 | 正确 |
| `EQEP_INT_INDEX_EVENT` | `EQEP_INT_INDEX_EVNT_LATCH` | 正确 |
| `EQEP_CONFIG_4X_RESOLUTION` | 不存在 | 正确 |
| 正交模式下固定 4X | **正确** | QSRC=00（正交）时，A/B 双沿天然 4X，XCR 位只对 CLOCK_DIR 模式生效 |

正交模式无法在硬件上切 1X/2X/4X，这点判断准确。原设计的“运行时切 1X 降 ISR 速率”必须放弃，改成软件步进（QPOSCMP ± N）是合理替代。

---

## 3. 问题三、四：QCPRD 16 位 + QCTMR 清零

**完全正确。**

- QCPRD/QCTMR 都是 16 位。SYSCLK=200 MHz 时，不分频最大约 327 µs。
- 低于约 46 rpm（4000 计数/圈）就会溢出。
- QCTMR 在每次 unit position event 后清零并锁存到 QCPRD，**不能**当自由运行绝对时间戳。

时间戳必须改用 CPU Timer（自由运行）+ 软件扩展 64 位，这是正确方向。

## 4. 方案 A（PCM 逐计数中断）评估

这是目前最接近“事件驱动”的可行方案，但有明显风险，需要重点验证。

### 优点
- 真正做到“每个（或每 N 个）计数变化一次中断”。
- 计数精确不丢（QPOSCNT 硬件累加）。
- 可用 QDC 处理方向反转重新武装。
- 分档用 N=1/2/4/8 软件降速，逻辑清晰。
- 时间戳用 CPU Timer 差分，不受 QCAP 16 位限制。

### 主要风险与坑

1. **ISR 负载**  
   4X @ 6000 rpm ≈ 400 k 边沿/s。即使 N=1，ISR 如果 >1 µs，CPU 占用就会很高。N 增大后中间边沿时间丢失，高速细节会打折扣（但比固定 1 kHz 采样好得多）。

2. **影子寄存器时序（PCSHDW + PCLOAD）**  
   匹配时硬件自动装载影子值。ISR 里写新的 QPOSCMP 必须保证：
   - 写完后再清标志。
   - 方向突然反转时，QPOSCNT 背离当前 CMP，可能漏掉一次匹配。  
   **必须用 QDC 中断重新武装**，否则会丢事件。

3. **回绕瞬间**  
   QPOSCNT 从 QPOSMAX 回到 0（或 Index 复位）时，CMP 匹配行为需要实测。建议把 QPOSMAX 设为很大（或按圈复位），减少回绕频率。

4. **ISR 追不上时的行为**  
   你的理解正确：计数不丢（读 QPOSCNT 差值可追赶），但中间边沿的精确时间戳丢失。这是优雅降级，可以接受。

5. **同一 INT_EQEP1 多源分发**  
   PCM + QDC + IEL 都进同一个 ISR，必须快速读 QFLG 并清对应位，否则会有标志残留导致重复进入。

### 建议的改进/加固

- 低速（N=1）用 PCM；中高速自动加大 N（根据最近速度估计）。
- ISR 开头先读 QPOSCNT 和当前时间戳，再处理标志，减少窗口。
- 增加“漏事件”计数器（本次 delta > N 就累加），联调时观察。
- 时间戳用 CPU Timer0 自由运行 + 1 kHz 维护高 32 位，ISR 里只读低 32 位做差分。

## 5. 其他可选方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **A. PCM 逐计数** | 真正事件驱动，时间戳精度高 | ISR 负载高，方向反转/回绕要小心处理 | ★★★★（首选） |
| **B. UTO 固定采样** | 实现最简单，最稳 | 丢失边沿时间细节，回到固定采样 | ★★（兜底） |
| GPIO XINT 边沿中断 | 真正边沿中断 | 无硬件 4X 解码，需要自己做正交解码，噪声敏感 | ★★ |
| CLB + XBAR | 灵活，可做自定义边沿逻辑 | 开发成本高，调试难 | ★（后期优化） |
| eCAP | 有边沿中断 | 只有 1–2 路，无法同时处理 A+B 正交 | 不适合 |

## 6. 对原项目设计的影响（必须改）

1. **核心架构**从“QCAP 捕获中断”改为“PCM 位置比较中断 + CPU Timer 时间戳”。
2. **分档**从硬件 1X/4X 改为软件 N 步进（N=1/2/4/8）。
3. **canonical counts** 仍然可以保持 4000 基准（正交模式天然 4X），非常好，继续保留。
4. **QCAP 可以彻底关闭**，不再依赖。
5. 原设计里所有“读 QCPRD 算速度”的地方，全部改成“相邻事件 t_us 差分”。
