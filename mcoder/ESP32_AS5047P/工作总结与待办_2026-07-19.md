## 1. 工作总结

### 目标达成（空载）

今日把「电机转速控制」空载主路径跑通并结案，并补上 **BLE 远距离遥控**：

1. **控制逻辑（S0–S3）**  
   - 前馈图 + 分区 PID  
   - 升/降不对称斜坡  
   - 加速度前馈 Ka≈0.05  
   - 减速积分/双增益 ADG（已对比；空载默认关）  
   - 1000…6000 闭环多点 PASS  

2. **执行器与协议**  
   - PWM 开环扫频至 **600 Hz**；闭环分步验收后工作默认 **400 Hz**（失败回 50）  
   - DShot 本台架不通 → **锁定 PWM**  
   - 停转 + 斜坡启动可靠（T4）  

3. **工程化**  
   - 自动测试脚本 + 单 COM 锁 + PING 保活  
   - 开环探点修复（MEASURE / open_pwm_hold）  
   - 方案文档与实测对齐  

4. **BLE 遥控（电机 + 磁编码器，非听声）**  
   - 固件 Nordic UART，广播名 **OEZ-RPM**；BLE 瘦身遥测默认 20 Hz  
   - PC：`encoder_monitor.py --ble`（Notify 不稳时 READ 兜底）  
   - 手机：`android/MotorBleControl` v1.0.3（转速/启停/设定/预设/近 8 s 曲线；未收到显示「未收到」）


### 关键认知

- 空载减速主要由 **DOWN 斜坡** 主导；S3 ADG 收益有限。  
- PWM 600 Hz 周期≈1667 μs，高油门易夹断 → 闭环工作点用 **400**（周期 2500 μs）。  
- FREQ400：V1–V6 + F 全 PASS（见 `FREQ400分步记录_20260719_124226.md`）。  
- **50 vs 400 闭环 A/B**：相当/噪声内（`FREQ50vs400对比报告_20260719_125723.md`）；400 不因跟踪更快而选，因脉宽余量。  
- DShot 失败更可能是电调未开数字协议，非「600 档不行」。  
- Windows/部分手机 **BLE Notify 不可靠**，可靠路径是 **周期 READ TX**（PC/App 均已做）。  
- `MotorPitchRpm` = 麦克风听声测转速；`MotorBleControl` = 台架编码器+电调 BLE 控制，二者勿混。
