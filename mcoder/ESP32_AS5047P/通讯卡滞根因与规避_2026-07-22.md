# 通讯被 shell 卡住：根因分类与规避

> 日期：2026-07-22  
> 项目：`E:\OEZCON\mcoder\ESP32_AS5047P`  
> 范围：USB/COM 主机链路与台架脚本；**不跑电机**。  
> 关联：总纲/架构见 `双核架构与采样改造建议_2026-07-22.md`、`工作日志_2026-07-22_AB架构.md`；与 PID/前馈分析任务并行时，本文件只谈通讯。

---

## 0. 一句话结论

台架上「通讯卡滞 / 电机莫名 ESTOP」多数不是电调或闭环本身坏了，而是 **PC 侧占口进程被打断或互抢 → 保活停 → 固件 `HOST_TIMEOUT(1.5s)` ESTOP**，再叠加 **满速遥测 / 阻塞打印 / Windows 串口独占** 把链路拖死。规避主线：**板载 `TEST` 判据 + 单占 COM + 测时禁 flash / 改固件时停 spin**；台架亦可 `HOST OFF` / `HOST TO <sec>`。

---

## 1. 根因分类

| # | 类别 | 机制 | 典型表象 |
|---|------|------|----------|
| 1 | **Shell / Agent 中断** | Cursor 工具调用超时、对话打断、多 agent 杀后台 → Python 退出 → 不再发 `PING`/`RPM` | 转速未起或刚起就 `# ESTOP host_timeout`；非 overspeed |
| 2 | **COM 互斥失败** | 多脚本 / monitor / 另一 agent 同时开 COM10；或 flash 与测试并行 | `Access is denied`、半截遥测、命令无 ACK、锁文件冲突 |
| 3 | **阻塞打印** | 2k 回调 / 400 控制里 `Serial.print` / 同步 `hostPrintf`（921600 下百字节级 ≈ ms） | 控制抖、overrun、遥测乱、偶发看门狗感「卡死」 |
| 4 | **HOST_TIMEOUT** | 默认 **1500 ms** 无主机指令且 `RUN_RUNNING` → `doEstop("host_timeout")`；`FLIGHT` / `LEARN` / **`test_active`** / **`HOST OFF`** 豁免 | 脚本停保活即急停；台架「被 shell 卡住」的直接保险丝 |
| 5 | **满速 USB 遥测** | 曾用过高帧率（跟控制满速刷）；串口 TX 占满 Core0/`loop` | 命令响应变慢、日志洪泛、看似「串口卡死」 |
| 6 | **Windows 串口特性** | 单设备独占；拔插换 COM；驱动/CDC 缓冲；句柄未关则下一进程打不开 | 烧录失败、脚本挂起、`PermissionError`；需杀残留进程 |

### 1.1 因果链（最常见）

```
多 agent / shell 打断 PC 脚本
        ↓
保活停止（无 PING/RPM）
        ↓
>1.5s 无指令 且 未 FLIGHT / 未 LEARN / 未 TEST / 未 HOST OFF
        ↓
固件 ESTOP host_timeout（油门→1000）
```

历史佐证：`pc/make_ff_pid_report.py` 写明「脚本被工具打断 → 保活停 → HOST_TIMEOUT」，而非 ESC 误保护；修复方向是 **独立后台进程 + ≤0.5s 保活**，或改板载 `TEST` / `HOST OFF`。

### 1.2 与板载 TEST 的关系（用户已定方向）

- 测试段应写进 ESP32；主机只发 **`TEST START` / `TEST STOP` / `TEST?`（及必要 OK 查询）**。  
- 判定（在转 / 误差 / 霍尔）在板内，避免长脚本挂在 shell 上被杀。  
- **设计意图**：`test_active` 期间禁用 HOST_TIMEOUT（与 `FLIGHT` 同级）。  
- **现状（已落实）**：`controlTick` 条件含 `!test_active`；`HOST OFF` / `HOST TO` / `HOST?` 可用。

## 3. 将来规避（可执行清单）

### 3.1 台架优先板载 TEST

1. 长段 / 阶梯 / 门闩：**优先 `TEST START <name>`**，主机只轮询 `TEST?` 或等摘要行，不要用长 Python 控油门。  
2. **TEST 运行中禁用 HOST_TIMEOUT**（已实现）。台架长时间不发令亦可 `HOST OFF`。  
3. 结束后 `TEST STOP` / `ESTOP` / `STOP` / `PWM 1000`，确认 `rpm≈0`。

### 3.2 PC 脚本仍用时（带通讯观测调参）

- **独立 OS 进程**；或先 **`HOST OFF`** 再低频轮询 / 收 20Hz 遥测。  
- 保活 ≤0.5s（未关超时时）；分析用 `TUNE?` / CSV 尾列 err,ff,u → `pc/tune_analyze.py`。  
- 改参仍串口：`LEARN` / `PID` / `GAIN`；勿在实时路径打印。  
- 异常路径先 ESTOP，再释放 `com_port_guard`。

### 3.3 单占 COM + flash/测试互斥

- 同时 **只允许一个** 占口任务（monitor / 测试脚本 / esptool）。  
- **flash 与闭环/TEST 互斥**：烧录前停 spin、停 TEST、释放锁；测时禁止 flash。  
- 异常后检查：`pc/logs/.com_port.lock`、残留 `python.exe`、设备管理器 COM 号。

### 3.4 Cursor / 多 agent 公约

| 场景 | 应做 |
|------|------|
| 改固件 / 编译 | **停** 电机 spin、**停** 占 COM 的测试脚本 |
| 跑台架 / TEST | **停** flash、**停** 其它 agent 占 COM10 |
| 并行分析（如 PID 文档） | 只写文件；不抢串口、不跑电机 |
| 已知冲突 ID | 与板载 TEST / flash 相关 agent 错开占口；通讯文档可并行 |

### 3.5 台架：`HOST` 命令（已落实）

| 命令 | 行为 |
|------|------|
| `HOST?` | 查询：生效态 + `cfg_ms` + flight/test/learn |
| `HOST OFF` / `HOST TO OFF` / `HOST TO 0` | 关闭主机超时（台架） |
| `HOST ON` | 恢复默认 **1.5s** |
| `HOST TO <sec>` | 设置超时秒数（约 0.2…120；过短钳到 200ms） |

- **飞行默认仍短超时或 FLIGHT 禁用**；勿把调试长超时当飞行常态。  
- `CTRL?` / `FLIGHT?` 报告 `host_timeout=` 含 flight/test/`HOST OFF` 豁免原因。

验收：

- `HOST OFF` → `START`（或不转只 arm 运行态）→ 故意数秒不发令 → **不应** `host_timeout`；再 `HOST ON`。  
- `TEST START idle`（或 smoke，**确认安全**）→ >2s 不发令 → **不应** `host_timeout`；`TEST STOP` 后恢复配置超时行为。
