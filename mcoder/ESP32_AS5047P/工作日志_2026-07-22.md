## 7500 静差与整定路径

### 诊断结论（`hi_step_7500_20260722_161754`）

| 量 | 值 |
|----|-----|
| 目标 | 7500 RPM |
| 稳态 enc | ≈7135（静差 −4.9%） |
| pulse | 卡在 ≈1508，**未**饱和（距 2000≈492µs） |
| 前馈图 | 末点 **6259RPM@1448µs**（`learn_relearn_20260721_181947`） |
| PID 修正 | u = pulse−ff ≈ **60µs** |

控制律：`pulse = ff + kp·err + ki·pid_i`，ADG OFF 时 `i_lim` 硬限原为 800。  
以板上典型 GainMap（kp≈0.025、ki≈0.062）估算：`P≈9` + `I_max≈ki·800≈50` → **u≈60**，与实测吻合 → **积分已触顶**。

| 因素 | 判定 |
|------|------|
| **前馈不足** | **主因**：目标 7500 > 图末 6259，`mapPulseFromRpm` 钳末点；FF 欠约 1200RPM |
| **Ki / i_lim** | **次因**：触顶后无法再抬油门；抬 i_lim 可暂补几十 µs，不能治本 |
| **400Hz 增益×1.6** | **否**：本固件 `pid_i += err*dt; u=ki*pid_i`，已含 dt，**勿**按 400/250 盲目放大 Ki |
| 其它 | 测速/过载正常（enc 2k、out 400、overrun=0）；非油门饱和 |

### 方案对比与推荐顺序

| 方案 | 内容 | 角色 |
|------|------|------|
| **A** | `RPMMAX≥8000` 下重跑 **LEARN RAMP**，扩展前馈到 ≥8000 | **治本，优先** |
| **B** | 升 `i_lim`（固件 ADG OFF 硬限已提到 1200）或微调 Ki；**不**做 1.6× 盲缩放 | 过渡/微调 |
| **C** | 板载 **TUNE** RAM 环 + 20Hz 遥测尾列 `err,ff,u` + PC `tune_analyze.py` | 观测与建议 |

**推荐顺序**：A → 用 C 验收 → 仍有静差再 B。  
**验收**：7500 稳态 |err|/7500 &lt; 2%（更好 &lt;1%），u 小（前馈命中），pulse 未贴 2000。

### 与 PC 通讯工作流对齐（防卡滞）

解决通讯卡滞后，**带着 PC 跑测试**：观测/分析/改前馈与 PID。

1. **防误 ESTOP**：`HOST OFF`（或 `HOST TO 0`）或走 **`TEST START …`**（段内关超时）；详见 `通讯卡滞根因与规避_2026-07-22.md`。  
2. **观测**：`TELEM ON` @20Hz；CSV 在原 25 列后追加 **err, ff, u**（索引 25–27）。或 `TUNE REC ON` → 结束后 `TUNE?` / `# TEST LOG`。  
3. **记录在 RAM**：TUNE 不依赖主机高频保活；实时路径禁打印。  
4. **调参仍用现有命令**：`LEARN RAMP`、`PID …`、`GAIN …`、`ADG ILIM …`、`PID SAVE` / `MEASURE SAVE`。  
5. **改固件 / flash**：与 TEST 任务错开占 COM；本轮文档+代码可不烧，由用户择时烧录。

板端命令：`TUNE REC ON|OFF`、`TUNE?`、`TUNE DUMP`；TEST 结束自动附 `# TEST LOG … hint=…`。  
PC：`pc/tune_analyze.py --summary` 或 `--from-line` / `--telem`。
