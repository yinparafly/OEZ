## 1. 方案建议核心提炼（`关于转速采样的问题.txt`）

面向场景：**高精度瞬时速度** + **电调输出固定 400Hz**。结论摘要：

| 维度 | 建议 |
|------|------|
| 采样率 | **首选 1200Hz**，次选 800Hz，不推荐 400Hz |
| 理由 | 400Hz ESC 窗口内：1200Hz≈6 点，可做最小二乘/滑动平均后再微分；延迟≈0.416ms；抗噪与扑翼 8–12Hz 负载波动响应最好 |
| 定时器 | **必须用硬件定时器（esp_timer）**，禁止用 `vTaskDelay` 跑 1200Hz（FreeRTOS tick 默认 1ms 调度不准） |
| 回调职责 | 定时器回调/ISR 中**只做「读取 → 入环形缓冲」**，再 **semaphore 通知**控制任务 |
| 控制/输出 | **400Hz** 控制任务（与电调刷新对齐） |
| 速度计算 | 在 **400Hz 控制任务**内，取环缓最近 **6 点**做最小二乘直线拟合得瞬时速度 |
| 模式口号 | **「高频采，低频控」** |
| ABI vs SPI | ABI/PCNT：读寄存器 <1µs，CPU≈0.12%@1200Hz；SPI：单次约 10–15µs，CPU≈1.8%@1200Hz——均可接受 |
| DMA | 文中 SPI 路径可配 DMA；非强制 |
| 双核 | 原文**未显式写核绑定**；其「定时器采 + 信号量唤醒控制任务」天然适合拆核 |

**与本项目的对应关系（预告）**：本项目已用 esp_timer 做到 **2kHz SPI 采样**（高于建议的 1200Hz），控制环仍 **250Hz**，电调默认 **50Hz**（可 `FREQ` 到 400–600）。测速在**采样回调内**做窗口差分+EMA，而非控制任务内 6 点最小二乘。**无显式双核 pin**。

## 2. 当前架构盘点（对照源码，非凭记忆）

### 2.1 编码器采样 / 测速

| 项 | 现状（源码） |
|----|----------------|
| 触发 | `esp_timer` 周期定时器，`ESP_TIMER_TASK` 分发（任务上下文，非硬 ISR） |
| 周期 | `ENC_SAMPLE_HZ=2000`，`ENC_SAMPLE_PERIOD_US=500` |
| SPI | `ENC_SPI_HZ=8000000`（8MHz），`setup()` 里 `beginTransaction` 常驻；回调内 `spiFrame`/`transfer16` |
| 解缠 | 回调内整型差分 ±8192，累加到 `int64 enc_cb_counts` → 快照 `g_enc.counts` |
| 测速窗口 | `ENC_VEL_WINDOW=8`（@2kHz=**4ms**），`rpm = Δcounts/CPR/Δt×60` |
| 滤波 | 尖峰拒绝 + EMA 0.9/0.1 + 符号锁定（~83ms 翻向） |
| 共享 | `portMUX_TYPE g_enc_mux` + 整块 `EncShared` 快照；**无** ring+semaphore |
| 实测（文档） | 采样率稳定 2000Hz；采样 CPU≈2.5–3%；主循环空转 ~7万–10万 Hz |

关键函数：`encSampleCb` / `encGetSnapshot` / `encoderBegin`（均在 `.ino`）。

### 2.2 控制环 / 遥测 / 霍尔 / BLE / 串口

| 子系统 | 现状 |
|--------|------|
| 控制环 | `CTRL_HZ=250`，`loop()` 用 `millis()` + `CTRL_MS=4` 节拍；`controlTick` → `applyEscPulse`（LEDC PWM 或 DShot） |
| 电调 | 默认 `ESC_PWM_HZ_DEFAULT=50`，`FREQ 50..600`；**非固定 400Hz** |
| USB 遥测 | 现状：每控制拍 `hostPrintf` 完整 CSV（≈250 行/秒）；**目标默认 20Hz**（完整帧率）；921600 |
| BLE | `bleBegin()` 启动即 advertising；NUS；默认 20Hz 瘦身行；RX 行进 `handleCommandLine` |
| WiFi | **固件未使用 WiFi**（无 `WiFi.begin` / OTA）；射频侧本就可保持关闭 |
| 霍尔 | `gpio_isr` ANYEDGE + 软件消抖；`hallDnIsr`/`hallUpIsr`（`IRAM_ATTR`）；主循环 `hallPoll` 消费 `volatile` 计数 |
| 串口命令 | `pollSerialCommands` 在 `loop()` 每次空转都跑；含 `HOST_TIMEOUT_MS=1500` 急停 |
| OTA | **无** `ArduinoOTA` |

### 2.3 FreeRTOS / 核绑定（关键）

源码检索结论：

- **没有任何** `xTaskCreate` / `xTaskCreatePinnedToCore`。
- 应用逻辑几乎全部在 Arduino **`loopTask` → `setup()`/`loop()`** 中。
- 编码器采样在 **esp_timer 系统任务**回调中执行（`dispatch_method = ESP_TIMER_TASK`）。
- 霍尔在 **GPIO ISR**（CPU 由 IDF 路由，非应用 pin）。
- BLE 协议栈由 Bluedroid/NimBLE 自建任务（通常偏 **Core0**）。

**Arduino-ESP32 默认行为（依据）**：

- 双核目标上，`setup()`/`loop()` 默认跑在 **`ARDUINO_RUNNING_CORE = 1`（Core1）**（IDE「Arduino Runs On」可改；Kconfig `ARDUINO_RUN_CORE1` 为默认）。
- `esp_timer` 任务亲和通常与系统配置相关，常见落在 **Core0** 或无亲和由调度器决定；**应用未显式 pin**。
- 因此现状是「**偶然**的跨核拆分」：高频采样多在系统/timer 侧，控制+遥测+串口在 Core1；**BLE 栈占 Core0**，与 esp_timer/SPI 存在潜在争用，但未主动管理。

### 2.4 线程安全

| 数据路径 | 机制 |
|----------|------|
| 编码器快照 | `portENTER/EXIT_CRITICAL(&g_enc_mux)`，单写（timer）单读（loop） |
| 霍尔沿 | `volatile` 计数/时间戳；主循环复制后处理（无 mux；32 位对齐写在 ESP32 上通常原子） |
| BLE RX 行 | `volatile bool g_ble_rx_has` + 双缓冲字符串；无临界区（单写回调/单读 loop，有竞态窗口但实践可接受） |
| SPI | 仅采样回调使用（控制环已不碰 SPI）；无多任务抢锁 |

## 2A. 采集率 vs 使用率（对照 `ESP32ReadAS5047P.ino`）

> **术语（用户规定；与 §2C 统一）**：  
> - **采集** = **2kHz SPI** 读角  
> - **使用** = **2kHz 求速**（**采 2k 用 2k**）  
> - **输出** = **400Hz PID→ESC**（目标；现状 250）  
> - **「取用」作废**：旧文「取用」= 今「使用」；**400Hz 是输出，不是使用/取用。**  
> **用户问（旧口径）**：「采样 2k，实际取用是不是 2k？比如实际取用只有 400Hz？」  
> **一句话结论（纠正后）**：现在是 **「2k 采集 + 2k 使用（回调内测速）+ 250Hz 输出」**。  
> - SPI + 解缠 + 窗口测速：**每秒约 2000 次** → 这是**采集/使用**（真 2k；采 2k 用 2k）。  
> - 控制环 PID / 写 ESC：**250Hz** → 这是**输出**（读快照里最新滤波 RPM，不再差分）。  
> - 口误「取用只有 400」应改为：**目标输出 400Hz**；**使用仍是 2k（或方案 1200），不是 400**。

### 2A.1 源码逐项核实

| 问题 | 源码事实 | 结论 |
|------|----------|------|
| `enc_sample_hz` / esp_timer 周期是否真每秒 2000 次 SPI+解缠？ | `ENC_SAMPLE_HZ=2000`，`ENC_SAMPLE_PERIOD_US=500`；`esp_timer_start_periodic`；`encSampleCb` 内 `spiFrame` 读 ANGLECOM + ±8192 解缠累加 `enc_cb_counts`；`g_enc.seq++`；loop 用 `seq` 差测 `enc_sample_hz_meas` | **是**：目标与实现均为 **2kHz 全路径采集**（每 100 拍另读一次 DIAAGC） |
| 测速在哪算？ | 回调内 `ENC_VEL_WINDOW=8`（@2kHz=**4ms**）窗口差分 → EMA 0.9/0.1 → 符号锁定 → 写入 `g_enc.rpm_signed` | **在 2kHz 回调里算（使用）**，不是只在 250Hz loop 用角度差分 |
| 控制环 `CTRL_HZ`？输出怎么用速？ | `CTRL_HZ=250`，`CTRL_MS=4`；`loop()` 用 `millis()`+`next_ms` 节拍；`encGetSnapshot` → `rpm_mag=fabsf(snap.rpm_signed)` → `controlTick(rpm_mag, dt)` | **输出 250Hz**；读**使用层最新滤波 RPM**，**不在控制拍重新差分**（`ddeg` 仅给 `phaseTick`/霍尔相位用） |
| USB / BLE 遥测？ | USB：`hostPrintf` 完整 CSV **每控制拍**（现状）；BLE：`bleEmitTelemLite` 默认 `BLE_TELEM_HZ_DEFAULT=20`，内部按周期限速（5–50 可调） | 现状 USB **≈250Hz**；**目标 USB 默认 20Hz**（完整帧率）；BLE 默认 **20Hz** |

### 2A.3 「1200 / 400 / 6 点 / 2400」含义辨析（对照 `关于转速采样的问题.txt`）

> 避免把「采样率」「差分端点」「6 点 LS」「控制率」混成一个数。

#### A. 相邻两点差分（用户澄清的「2400」语义）

若测速是 **ω = (θ_now − θ_prev) / Δt**：

| 项 | 数值 |
|----|------|
| 每秒唯一点（SPI/角度） | **1200** |
| 每秒差分次数 | **≈1200**（稳态下每新点一次；首点无 prev 时少 1） |
| 「2400」 | **1200×2 个端点引用**，或 **1200 对 (θ_k, θ_{k−1})**——**不是**新产生 2400 个唯一点 |
| 每 2.5ms 控制拍新点 | **1200÷400 = 3** |

✅ **用户「2400 = 两点差分端点」理解正确**（在「相邻差分」语义下）。

#### B. 原文到底写了哪种测速？——两种都写了，推荐的是 6 点 LS

| 出处 | 原文说法 | 算法 |
|------|----------|------|
| 对比表 / 深度解析 | 400Hz「仅能做一阶差分」；800Hz「4 点线性拟合」；1200Hz「**6 点最小二乘** / 滑动平均后再差分」 | 强调：相邻两点差分噪声大；采密是为了**多点拟合** |
| 最终配置（文末） | 「在 400Hz 控制任务中，取环缓内**最近 6 个点**做最小二乘直线拟合」 | **推荐实现 = 控制侧 6 点 LS**，不是每拍只做一次相邻差分 |

因此：

- **2400 = 1200×2 端点**：对应「相邻差分」计数方式——逻辑自洽，但**不是原文最终推荐算法的计数**。
- **原文推荐**：400Hz 控制拍上对**近 6 点**做 LS（每拍引用 6 点 → 若硬算引用次数是 400×6=2400，那是另一套账，**不要与「1200×2 端点」混用**）。
- 对比表「2.5ms 内 6 点」与采样率算术（应 ≈3 新点/拍）不一致——**以文末「取最近 6 点」为准**；6 点窗跨 5 个采样间隔 ≈ **4.17ms**。

#### C. 400Hz 输出如何用这些速度？

| 路径 | 控制拍怎么用速度 |
|------|------------------|
| **原文推荐** | 每 2.5ms **在控制任务内**对环缓近 6 点做一次 LS → 得到**本拍一个** ω → PID → 写 ESC。**不是**「把本拍内 3 次相邻差分再平均」 |
| **若用相邻差分 @1200** | 采样侧可每点更新 ω；400Hz 控制通常 **只取最新一次** ω（或最新滤波值）写 ESC——仍是「采密、控疏」 |
| **ISR 职责（原文）** | 定时器回调**只读角度入环缓** + 信号量；算速在 400Hz 控制任务 |

#### D. 与本项目现状对照（同样「采密、控疏」）

| 项 | 方案原文（建议） | 本项目现状 |
|----|------------------|------------|
| 采样 | 1200 Hz | **2000 Hz** |
| 测速更新 | 推荐：控制侧 6 点 LS @400；若相邻差分则 ≈1200 次/s | 采样回调内 **8 点窗差分 + EMA @≈2000**（每秒约 **2000 次**窗差分更新） |
| 「端点」口语 | 相邻差分时 1200×2=2400 | 窗差分每拍用窗首尾 2 点（窗长 8）；**不是** 2000×2 唯一点 |
| 控制 | 400 Hz | **250 Hz** |
| 控制如何用速 | 每拍算/取一个 ω | **只取最新滤波 RPM**，不再在控制拍差分 |
| 口号 | 高频采，低频控 | ✅ 同构：2k 采集/使用 / 250 输出 |

### 2A.4 给用户的直接答案（现状 2k）

| 说法 | 对不对 |
|------|--------|
| 「现在采集真的是 2k（SPI）」 | ✅ 对 |
| 「现在使用（求速）也是 ≈2k」 | ✅ **对**——采 2k 用 2k；在采集回调里算速 |
| 「现在输出也是 2k」 | ❌ **不对**——输出现状是 **250Hz**（目标 400） |
| 「取用只有 400Hz」 | ❌ **不对**——旧「取用」已废；把输出误叫成使用；使用≈2k；**400 是目标输出** |
| 「2k 采集/使用、低频输出」 | ✅ **对**——目标改为输出 **400Hz**，弃 250 |
| 「采集/使用 2k ≠ 输出 2k」 | ✅ **必须坚持**；目标：**采集/使用保持 2k（或 1200），输出对齐 400Hz** |

数据流（现状）：

```
esp_timer @2000Hz（采集 SPI + 使用求速）     loop @250Hz（输出）
  SPI → 解缠 → 8点窗差分+EMA  →  encGetSnapshot()
  写 EncShared.rpm_signed     →  controlTick(最新|rpm|) → applyEscPulse
                              →  USB CSV @250 / BLE lite @20
```

## 2B. 多任务分频（对照 FreeRTOS 独立任务建议）

> 用户粘贴建议核心：不同频率用**独立任务** + `vTaskDelayUntil`；电机控制高优先级 pin Core1；通信低频；硬件定时器触发采样更专业；固定核心避免缓存抖动。

### 2B.1 现状对照：已拆任务了吗？

| 建议项 | 现状（源码） | 判定 |
|--------|--------------|------|
| 不同频率独立任务 + `vTaskDelayUntil` | **无** `xTaskCreate` / `vTaskDelayUntil`；控制+USB 遥测+串口命令全在 Arduino **`loop()`**，用 `millis()`+`next_ms` **嵌套节拍** | ❌ 仍是「单任务嵌套计数器」 |
| 电机控制高优 pin Core1 | 无显式 pin；`loop` 默认跑 Core1（Arduino 默认），优先级未单独抬高 | ⚠️ 偶然在 Core1，非刻意 |
| 通信低频独立 | USB 与控制同拍 250Hz；BLE 在同 `loop` 里限速 20Hz；无独立通信任务 | ⚠️ 仅 BLE 限速，未拆任务 |
| 硬件定时器触发采样 | **已有** `esp_timer` @2kHz → `encSampleCb`（`ESP_TIMER_TASK`） | ✅ 已做（且高于原文 1200Hz） |
| 固定核心避抖动 | 应用未 `xTaskCreatePinnedToCore`；BLE 栈常占 Core0，与 timer/SPI 潜在争用 | ❌ 未主动管理 |

**结论**：当前 = **「esp_timer 2kHz 采样 + `loop` 单任务嵌套 250Hz 控制/遥测」**，**尚未**按 FreeRTOS 多频率独立任务拆分。

### 2B.2 与既有文档 / `关于转速采样的问题.txt` 对齐

| 来源 | 口号 / 要点 | 与现状 | 与推荐改造 |
|------|-------------|--------|------------|
| `关于转速采样的问题.txt` | 「高频采，低频控」；esp_timer 采；控制/输出 **400Hz**；控制侧取近 N 点算速 | 采已 2k（优于 1200）；控仍 250；测速在**采样回调**非控制侧 | 控→400 + ESC 400；可选测速下沉 |
| 本文 §1 / §4–5 | 采样保持 2k；控制/ESC 对齐 400；测试开 BLE / 飞行关；可选 pin Core1 | 文档已写，代码未全落地 | 继续阶段 A→B→C |
| 用户 FreeRTOS 建议 | 独立任务分频 + 控制高优 Core1 + 定时器采样 | 仅定时器采样已落地 | **推荐采纳分任务形态**，但 **输出频率对齐 400，不要上到 2k** |

要点重申：**采集/使用 2k ≠ 输出 2k**。2k 服务观测质量；**输出**应对齐电调 **400Hz**（400 ≠ 使用；「取用」作废）。

### 2B.3 推荐目标架构表

| 任务 | 频率 | 核 | 优先级 | 实现 |
|------|------|----|--------|------|
| **编码器采样** | **2000 Hz** | 随 esp_timer 任务（常见 Core0；可不强 pin） | 系统 timer 任务级 | **`esp_timer` 周期回调**（保持）；职责尽量短：SPI+解缠+写环缓/快照；（可选）窗口测速仍可放此，或迁控制侧 |
| **电机控制** | **400 Hz**（目标；现状 250） | **Core1** | **最高应用优先级**（如 4–5） | `xTaskCreatePinnedToCore` + **`vTaskDelayUntil`**；每拍读**使用层最新 RPM**（或环缓近 6 点 LS）→ PID/斜坡 → `applyEscPulse`；**此 400Hz = 输出，≠ 使用** |
| **ESC 输出帧** | **400 Hz**（与控制对齐；现状默认 50） | 硬件 LEDC / DShot 比特流 | — | `FREQ 400`（PWM）或 DShot 速率配置；控制拍改脉宽/油门值 |
| **USB 串口命令 + 遥测** | 命令：尽量每次泵；遥测默认 **20 Hz**（完整帧率＝20 行 CSV/秒；旧稿「100Hz」＝100 帧/秒，现定 20） | Core0 或低优 Core1 | 低（1–2） | 独立任务或降级后的 `loop`；**只读快照**；与采集2k/使用2k/输出400无关；勿堵控制临界路径 |
| **BLE NUS** | 遥测默认 **20 Hz**；RX 事件驱动 | **Core0**（栈已在此） | 低 | 测试态 ON；**飞行态 OFF**（`BLE OFF` / 编译关）；勿与控制同优先级 |
| **霍尔** | 边沿事件（非固定 Hz） | ISR（IDF 路由）→ 控制拍消费 | ISR 最高；处理在控制任务 | `gpio_isr` 只记时间戳/计数；`hallPoll` 在控制任务 |

目标数据流：

```
esp_timer @2000Hz                 ctrlTask @400Hz (Core1, 高优)
  SPI → 解缠 → 快照/环缓    →     取最新 rpm（或 6 点 LS）
                                → PID → applyEscPulse → ESC @400Hz

commTask / loop（低优）           BLE 栈（Core0，仅测试）
  串口命令 + USB 遥测 @20Hz         NUS RX/TX @~20Hz
```

> **USB 遥测 Hz 写死**：**Hz = 完整遥测帧率**（每秒 N 行 CSV），不是帧内计算次数。原先草案「**100Hz**」＝100 帧/秒；现用户定 **20 帧/秒**。与采集2k / 使用2k / 输出400 **无关**——遥测只读快照。

**刻意不做**：把**输出**升到 2kHz——电调只需 ~400Hz 刷新；升到 2k 只会浪费 CPU、放大 PWM 改写抖动，且违背「高频采集/使用、低频输出」的工程分工。

## 2C. 节拍对齐：弃 250、采 200/400 整数系

> **用户问**：400Hz 控电机时，250 总频不易对齐；若总周期按 **200Hz**，电机控制独立 **400Hz**，各循环自循环，是否更易控？  
> **术语必须写死（用户规定；「取用」作废）**：
>
> | 词 | 含义 | 目标频率 | **禁止** |
> |----|------|----------|----------|
> | **采集**（采集数据） | **2kHz SPI** 读角入缓冲 | **1200Hz**（方案下限）或现状 **2000Hz** | — |
> | **使用**（使用数据） | **2kHz 求速**（差分/窗拟合等）；**采 2k 用 2k** | **1200Hz**（或现状 ≈**2000Hz**） | **禁止把 400Hz 叫「使用」**（旧「取用」同禁） |
> | **输出**（输出数据频率） | **400Hz PID→ESC** | **400Hz** | 勿与采集/使用混称 |
>
> **写死数据流**：
> ```
> 采集 @1200 或 2kHz（SPI） → 使用 @同频（求速，采2k用2k）→ 得到速度 ω
>         ↓
> 输出 @400Hz 读「最新速度」→ PID → 写 ESC/PWM
> ```
> 每输出拍**消费最新使用结果**（最新差分速度，或近 6 点拟合），**不是**把 400Hz 当成使用频率。

### 2C.1 为何 250 与 400 难对齐

| 关系 | 数值 | 问题 |
|------|------|------|
| 400 ÷ 250 | **1.6** | **非整数倍** |
| 最小公倍数（Hz） | **2000** | 要以「同一大循环嵌套分频」硬对齐，得上到 2k 拍才能同时整除 250 与 400 |
| 同 loop 嵌套 | 每 4ms 控一拍 vs 每 2.5ms 出一拍 | 计数器/相位别扭，易抖、难对日志 |

结论：把「总周期」钉在 **250Hz**，再叠 **400Hz 输出**，同一嵌套 loop 几乎必然别扭 → **弃用 250 作系统/控制基准**。

### 2C.2 「总周期 200Hz + 各循环自循环」评估（术语已纠正）

**写死目标数据流（本工程）**：

```
esp_timer 采集/使用 @2000Hz（SPI+求速；可降至 1200；采2k用2k）
        → EncShared / 环缓：最新 ω（或角度点列）
ctrlTask 输出 @400Hz（Core1，vTaskDelayUntil 2.5ms；PID→ESC）
        → 读最新 ω → PID/斜坡 → applyEscPulse
ESC @FREQ 400（与输出同相最佳）
sysBeat @200Hz（可选）：状态机/看门狗/日志节拍——不跑 PID、不写 ESC
遥测/BLE：USB **20Hz** / BLE **20Hz** 独立任务（Hz＝完整帧率）
```

| 问题 | 答案 |
|------|------|
| **200Hz 总周期是否仍建议作系统节拍（状态/日志）？** | **是**——作「系统节拍基准」可以：看门狗、模式状态、低频日志。**不要**在 200Hz 大循环里嵌套算电机；电机走独立 400Hz 任务。 |
| **电机控制是否仍独立 400Hz，并读取 1200/2k 使用层结果？** | **是**。400Hz = **输出**；它**读取** 1200/2k **使用层**已算好的最新速度（或控制拍内对近 N 点再拟合）。**使用本身仍是 1200/2k，绝不是 400。**（旧「取用」=使用，已废。） |
| 200 与 400 对齐？ | **2:1** 整数比：每 5ms 系统拍内输出可跑 **2** 次；或控制任务独立 `vTaskDelayUntil(2.5ms)`，与 200Hz 任务只共享时间基准、不互相嵌套。 |
| 与 ESC | **首选 `FREQ 400` 与输出同相**（每拍写一次脉宽即生效）。若 ESC=200：输出 400 则每 ESC 硬件帧内改写 **2** 次脉宽，**末值生效**——多一次无效写、相位略糊，不如同 400。 |
| 与采集/使用 | **2k**：2000/400=**5**，2000/200=**10**；**1200**：1200/400=**3**，1200/200=**6**——均为整数，很好。 |
| 遥测/通信 | USB **20**、BLE **20** 独立任务即可，**不必绑 250/400**；遥测只读快照，与采集2k/使用2k/输出400无关。 |
| FreeRTOS 形态 | **推荐各任务 `vTaskDelayUntil`（或 esp_timer 采）**；200Hz 只作可选 sysBeat。**不推荐**「200Hz 大循环里 for/if 嵌套分频」。 |

**利弊摘要（相对现状 250）**：

- **利**：全链路整数比（2k/1200 ↔ 400 ↔ 200）；弃掉 1.6× 别扭；输出易与 ESC 400 同相；日志/状态用 200 干净。  
- **弊/注意**：升 250→400 后 PID/ki 需复核；ESC 若仍停在 50/200，会出现「输出写快、硬件帧吃末值」——台架应 `FREQ 400`。

### 2C.3 推荐干净整数关系表

| 链路 | 频率 | 角色（用词） | 与 200Hz 关系 | 与 400Hz 输出 |
|------|------|--------------|---------------|---------------|
| 编码器采集 | **2000**（或 **1200**） | **采集**（2kHz SPI） | 10× / 6× | 5× / 3× |
| 测速/差分/拟合 | **同采集 ≈2k 或 1200** | **使用**（采 2k 用 2k） | 同上 | 每输出拍读最新结果 |
| PID→写 ESC | **400** | **输出** | 2× | 1×（自身） |
| ESC PWM 帧 | **400**（`FREQ 400`） | 执行器刷新 | 2× | **同相 1:1** |
| 状态/看门狗/日志 | **200** 或 **100** | 系统节拍（非使用、非输出） | 1× / 0.5× | 1/2 或 1/4 |
| USB 遥测 | **20**（完整帧率；旧稿 100→现定 20） | 通信 | 1/10 | 远低于输出；只读快照 |
| BLE 遥测（测试） | **20** | 通信 | 1/10 | 远低于输出 |

### 2C.4 与现状同构：弃 250，输出改 400

| 层 | 现状 | 目标 | 是否改 |
|----|------|------|--------|
| **采集** | 2000 Hz（SPI） | 保持 **2k**（或方案下限 **1200**） | 可保持 2k |
| **使用**（求速） | ≈**2000 Hz**（采集回调内窗差分+EMA） | 保持与采集同层 **2k**（采 2k 用 2k） | **不是**改成 400；（旧「取用」已废） |
| **输出** | **250 Hz** | **400 Hz**（PID→ESC） | **弃 250 → 改 400** |
| **ESC** | 默认 50（可 FREQ） | **FREQ 400** 与输出对齐 | 台架必改 |
| **系统节拍** | 无独立；loop 嵌 250 | 可选 **200 Hz** sysBeat | 新增可选 |

同构口号（纠正后）：

- 现状：**高频采集/使用（2k） + 低频输出（250）**  
- 目标：**高频采集/使用（2k 或 1200） + 低频输出（400）**；可选 **200Hz** 仅作状态/日志节拍  
- **400 = 输出，≠ 使用**（勿再写「取用」）

### 2C.5 给用户的直接结论

1. **更易控制吗？** —— **是**。200 与 400 为 2:1，远好于 250 与 400 的 1.6:1。  
2. **总周期怎么定？** —— **200Hz 可作系统节拍（状态/看门狗/日志）**；**不要**当电机大循环母体。  
3. **电机怎么定？** —— **输出独立 400Hz**；每拍用采集/使用层（1200 或 2k）的**最新速度**写 ESC；ESC 用 **FREQ 400**。  
4. **要弃 250 吗？** —— **要**。250 既难与 400 对齐，又不是使用频率；使用保持 2k（或 1200），只把输出 250→400。

## 3. 差距对比：方案建议 vs 现状

| 建议项 | 现状 | 判定 |
|--------|------|------|
| 采样 ≥1200Hz（硬定时器） | **2kHz esp_timer** | ✅ **已做且更优**（量程/抗折叠已验证） |
| 禁止 vTaskDelay 高频采样 | 未用 delay 采样 | ✅ 已做 |
| 回调极简：只读+入环缓 | 回调内：SPI+解缠+窗口差分+EMA+符号锁+写快照 | ⚠️ **部分**：逻辑偏重，但仍在 timer 任务上下文可接受 |
| semaphore 唤醒控制任务 | portMUX 快照轮询 | ❌ 未做（可用但非必须） |
| 控制 400Hz + ESC 400Hz 对齐 | CTRL=250，ESC 默认 50（可 FREQ） | ❌ **未对齐** |
| 控制任务内 6 点最小二乘测速 | 采样侧 8 点窗口差分+EMA | ⚠️ 效果同类，算法不同；LS 可迁到控制侧作增强 |
| SPI-DMA | 同步 SPI；文档称 ~2.5% CPU | ⚪ 可选，暂无必要 |
| ABI/PCNT | 未接 | ⚪ 未来可选 |
| 显式双核 pin | 无 | ❌ 未做；靠默认 Core1 loop + Core0 栈 |
| 测试 WiFi 关 | 本就未开 WiFi | ✅ 已满足（保持即可） |
| 测试 BLE 开 / 飞行 BLE 关 | 上电即 `bleBegin()`+advertise，**无飞行关断** | ❌ 缺运行时/编译切换 |

**双核是否合理（结论）**：

- **方向大体合理**：硬实时采样已不在 `loop` 里阻塞 SPI；控制在 Core1。  
- **不合理点**：未显式隔离；测试态 BLE 与 esp_timer/SPI 同挤 Core0；控制节拍与 ESC 刷新未对齐；飞行态无法关掉 BLE 把 Core0 让给采样。  
- **不建议为了「凑核」立刻大拆任务**：当前 CPU 余量极大；优先做 **通信模式切换 + 控制/ESC 对齐 +（可选）测速算法下沉**。

## 4. 推荐双核分工

### 4.1 统一原则

1. **Core1 = 控制确定性核**：PID/斜坡、写 ESC（PWM/DShot）、急停、（可选）测速拟合；高优先级、少阻塞 I/O。  
2. **Core0 = 通信与系统核**：BLE 栈（仅测试态）、USB 串口重度打印可缓、WiFi 永不默认开启。  
3. **采样路径**：继续 **esp_timer**（µs 级）；回调保持短；**飞行态关 BLE 后，Core0 上 timer/SPI 抖动显著下降**。  
4. **霍尔 ISR**：保持极短；主逻辑仍在控制拍消费。

### 4.2 测试态（台架 / 手机调试）

| 核 | 负责 | 不做 |
|----|------|------|
| **Core1** | `loop`/控制任务：250→**建议 400Hz** 控制；`applyEscPulse`；串口命令解析（轻）；取编码器快照 | 不在控制拍里做大块 `Serial` 刷屏以外的阻塞；避免在临界区里 notify BLE |
| **Core0** | BLE 栈 + NUS RX/TX；esp_timer→SPI 采样（现状）；（可选）USB 遥测独立低优任务默认 **20Hz** | **不开 WiFi**；OTA 默认关 |
| **任意核 ISR** | 霍尔 GPIO ISR（只记时间戳/计数） | 不做 SPI/浮点重算 |

测试态通信：

- **WiFi：关闭（默认）**——固件本无 WiFi；若日后引入，须 `WIFI OFF` 默认且测试脚本不启 AP/STA。  
- **蓝牙：开启**——保留 NUS 调试/手机控；遥测继续限速瘦身（默认 20Hz）。

### 4.3 飞行态（正式飞行）

| 核 | 负责 | 变化相对测试态 |
|----|------|----------------|
| **Core1** | 控制环 + ESC 输出（建议与电调 **400Hz** 对齐） | 同左；可略提高控制任务优先级 |
| **Core0** | **仅** esp_timer 采样 +（极轻）系统；无 BLE 栈争用 | **关 BLE**：停 advertising、断连、`BLEDevice::deinit` 或等价；Core0 让给采样 |
| 通信 | **USB 可选仅地面联调**；空中无无线调试依赖 | 主机超时策略需改为「飞行无主机」模式（见风险） |

飞行态通信：

- **蓝牙：关闭**（无 advertising / 无 NUS / 无 notify）。  
- **WiFi：保持关闭**。  
- 好处：Core0 协议栈 CPU/中断/射频干扰下降 → **2kHz 采样周期抖动减小**、控制环取快照更干净；省电、减 EMI。

### 4.4 测试态 vs 飞行态对照表

| 项目 | 测试态 | 飞行态 |
|------|--------|--------|
| WiFi | OFF（本就未开） | OFF |
| BLE advertising / NUS | ON | **OFF** |
| BLE 遥测/遥控 | ON（限速） | 无 |
| USB 串口 | ON，遥测默认 **20Hz**（完整 CSV 帧率） | 地面可开；空中不依赖 |
| 编码器采样 | 2kHz esp_timer（可保留） | 同左（更干净） |
| 控制环 | 建议升至 400Hz | 400Hz + ESC 400Hz |
| Core0 主要负载 | BLE + timer/SPI | **几乎只有 timer/SPI** |
| Core1 主要负载 | 控制 + 串口/轻 BLE 泵 | 控制（更纯） |
| 主机超时急停 | 保留（防台架失控） | 需 `HOST TO OFF` 或飞行模式关闭超时 |

## 5. 分步修改方案（可落地，先文档后代码）

### 阶段 A — 通信模式（优先，改动小、收益直接）

**目标**：落实「测试开 BLE / 飞行关 BLE / WiFi 永不默认开」。

| 步骤 | 文件 | 内容 |
|------|------|------|
| A1 | `ble_host.h/.cpp` | 新增 `bleEnd()` / `bleSetEnabled(bool)`：停 adv、断连、可选 `BLEDevice::deinit()`；`bleEmit*`/`bleTakeRx` 在关闭时短路 |
| A2 | `.ino` | 命令：`BLE ON` / `BLE OFF` / `BLE?`；可选 `FLIGHT ON`（关 BLE + 关主机超时或放宽）/ `FLIGHT OFF` |
| A3 | 编译开关 | `#define FEATURE_BLE_DEFAULT 1`（测试固件）/ `0`（飞行固件）；`setup()` 仅当默认开才 `bleBegin()` |
| A4 | WiFi | 保持不用；若引入则默认关 + `WIFI OFF`；文档与脚本禁止测试误开 |
| A5 | Banner | 打印 `mode=TEST|FLIGHT ble=on|off wifi=off` |

**验收**：`BLE OFF` 后手机扫不到 OEZ-RPM；`ENC?` 采样率仍 2000；USB 控制仍可用。

### 阶段 B — 控制与 ESC 对齐（衔接方案建议的 400Hz）

**与现有 2kHz 采样衔接**：

```
esp_timer @ 2000Hz          控制任务 @ 400Hz              ESC @ 400Hz
  SPI → 解缠 → 环缓/快照  →  每 2.5ms 取快照(或取近 6 点)
                            → LS/窗口差分得 rpm
                            → PI → applyEscPulse ──────────→ LEDC 400Hz
```

| 步骤 | 建议 |
|------|------|
| B1 | 增加配置：`CTRL_HZ=400`（或 `CTRL_HZ` 跟随 `esc_pwm_hz` 当 ESC∈{50,250,400}） |
| B2 | 台架验证：`FREQ 400` + 控制 400Hz；先空载 CLOSED，看超调/静差 |
| B3 | **不要**把采样降到 400；**保持 2kHz**（已验证不折叠；1200 为建议下限，2k 更宽裕） |
| B4 | 可选：把测速从回调挪到控制任务——回调只写 `(t_us, counts)` 环缓；控制拍对最近 6 点做最小二乘；EMA/符号锁可留控制侧 |

涉及函数：`loop` 节拍、`controlTick`、`encoder` 环缓 API、可选新建 `ctrlTask`。

### 阶段 C — 显式双核 pin（中等改动，建议在 A/B 后）

| 步骤 | 内容 |
|------|------|
| C1 | `xTaskCreatePinnedToCore(ctrlTask, …, prio≥2, Core1)`：控制+ESC；`loop()` 降为通信泵（串口/BLE 命令+可选降频遥测）或 `loop` 空转 `vTaskDelay` |
| C2 | 保持 esp_timer 采样；**不**把 SPI 放进硬 ISR（`ESP_TIMER_ISR`）除非改 DMA |
| C3 | 测试态：BLE 留 Core0；飞行态：`BLE OFF` 后观察 `enc_sample_hz` 抖动与 `enc_cpu_pct` |
| C4 | 可选诊断：`CORE?` 打印 `xPortGetCoreID()`（loop / 采样回调内采样一次） |

**暂缓**：SPI-GDMA、ABI+PCNT（见既有 `高频采样改造_2026-07-21.md` P2）。

### 阶段 D — 测速算法增强（可选）

- 控制侧 6 点最小二乘（对应方案文「甜点」）；2kHz 下 6 点≈3ms 窗，与现 8 点/4ms 接近。  
- 扑翼周期负载下对比：窗口差分+EMA vs LS（超调、纹波、霍尔交叉误差）。  
- 符号锁定/EMA 在 flap 工况再整定（既有 TODO）。

### 5.1 推荐改动文件清单（实施时）

| 文件 | 改动要点 |
|------|----------|
| `ESP32ReadAS5047P.ino` | 模式开关、CTRL_HZ、可选 ctrlTask pin Core1、环缓消费、命令、banner |
| `ble_host.h` / `ble_host.cpp` | `bleEnd`/`bleSetEnabled`、关闭时短路 TX/RX |
| （可选）新 `enc_ring.h` | 轻量 `(t_us,counts)` 环 + 读指针；mux 或原子 |
| 文档/脚本 | 测试流程默认 `WIFI` 不用；飞行构建或 `FLIGHT ON`；勿在飞行固件依赖手机 NUS |

### 5.2 与「2kHz 采样 + 250Hz 控制」如何衔接（决策）

| 选项 | 做法 | 建议 |
|------|------|------|
| **保持 2kHz 采样** | 不动 `ENC_SAMPLE_HZ` | **推荐**：已验证；高于 1200 建议 |
| 控制 250→400 | 改 `CTRL_HZ`，ESC `FREQ 400` | **推荐（下一硬件相关步）** |
| 采样降到 1200 | 仅为「贴原文」 | **不推荐**：无收益，浪费已验证余量 |
| 回调瘦身 | 测速迁控制任务 | 可选增强，非阻塞 |
| DMA | 仅当采样 >4kHz 或 Core0 仍紧 | 暂缓 |

## 6. 风险与验收标准

### 6.1 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 飞行关 BLE 后主机超时 | 现逻辑依赖主机保活 1.5s | `FLIGHT ON` 时关闭 `HOST_TIMEOUT` 或改「仅 USB 连接时启用」 |
| `BLEDevice::deinit` 后再开 | 部分栈复初不稳定 | 飞行固件编译期关 BLE；测试固件用运行时 OFF 即可 |
| 控制升 400Hz | PID/GainMap 按 250Hz 整定 | 升频后复核超调/静差；必要时缩放 ki |
| ESC 400Hz 脉宽夹断 | 周期 2500µs，2000µs 脉宽仍可行 | 沿用现有 `applyEscPulse` 夹断逻辑 |
| 双核拆任务竞态 | 命令改 `target_cmd` vs 控制读 | 对指令用 mux 或「命令队列 + 控制拍消费」 |
| Core0 上 SPI+BLE 同挤 | 测试态采样抖动 | 测试可接受；飞行关 BLE 验证改善；必要时降低 BLE 遥测率 |

### 6.2 验收标准

**通信模式**

- [ ] 上电默认：WiFi 未启动；测试固件 BLE 可连；banner 标明模式  
- [ ] `BLE OFF` / `FLIGHT ON`：无广播、无 NUS；USB 命令仍可用  
- [ ] 飞行固件（`FEATURE_BLE_DEFAULT=0`）：不初始化 BLE 栈  

**采样（回归）**

- [ ] `ENC?`：`meas_hz≈2000`，`cpu%` 仍低（飞行态不劣于测试态）  
- [ ] 2000/4000/6000RPM 与霍尔交叉误差仍 <1%（空载）  

**控制对齐（若做阶段 B）**

- [ ] `FREQ 400` + `CTRL_HZ=400`：闭环稳态静差/超调不差于当前 250Hz 基线（或可解释的整定差异）  
- [ ] 急停/ESTOP/HOST 策略按模式正确  
- [x] **实时路径禁打印（硬验收）**：`encSampleCb`(2k) 与 `motorControlTask`(400) 内禁止 `Serial.print`/`hostPrintf` 直打；meta 入异步环，由低优 `telemTask`/`hostDrainAsyncLog` 排出；USB 遥测不得跟 400Hz 满速刷（≤20Hz `Serial.write`）  

**双核（若做阶段 C）**

- [ ] `CORE?` 显示控制在 Core1、采样回调核稳定  
- [ ] 飞行态关 BLE 后控制拍间隔抖动不恶化

## 7. 下一步建议（执行顺序）

1. **先做阶段 A（通信模式）**：`BLE OFF`/`FLIGHT` + 编译开关；WiFi 保持不用——满足用户测试/飞行约束，且几乎不动控制数学。  
2. **再做阶段 B**：台架将 ESC+控制对齐 **400Hz**，采样保持 **2kHz**。  
3. **按需阶段 C**：仅当测试态见 BLE 导致采样抖动/丢拍时，再显式 pin 控制任务到 Core1、并加 `CORE?`。  
4. **可选阶段 D**：控制侧 6 点最小二乘，与现窗口差分 A/B 对比（扑翼负载）。  
5. **仍暂缓**：DMA、ABI/PCNT、大规模重构；**不在本轮烧录/跑电机**（除非后续单独授权）。
