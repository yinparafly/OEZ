## 0. 先答旧问：目视停在 ~200° 是什么？

依据已落盘日志（无新 COM），**不是「测试中途随意 ESTOP」**，而是 **目标 0° 的 HOLD 已跑完，固件盘相位却落在 ~189°**：

| 来源 | 证据 |
|------|------|
| `pc/logs/hold_phase_strategy_cmp_20260722_194014.txt` | 策略 `C_agg_soft200_hold0`：`HOLD PHASE 0` → `DONE reason=settle_hall target=0.0 disc=188.76 hall_confirm=1`，`|err|=171.24`，判定 FAIL |
| 同文件多数其它策略 | `DONE disc` 在 **≈0° 或 349°–360°**（固件标架下接近 0） |
| 套件末尾 | 有收尾 `ESTOP`，属脚本清理，**不是**上述 ~189° 那次的停因 |

**结论**：

1. **那次 ~200°**：属 **「目标 0 却 miss 到固件 ~189°」**（急停策略 C：高转速进场 + `stop_ms=0` 立刻爬行，霍尔先于 lead 触发 `hall_dn_before_lead`，滑行后 settle 在半圈附近）。  
2. **不是**随机掐断；也 **不能**单凭「固件 disc≈0」断言目视也是物理 0（见 §3 OFFSET）。  
3. 选圈/减速比算对了，**不修复** 0↔180 标架；标架错仍靠 `PHASE OFFSET` / 霍尔接线核对。

## 1. 传感模型（钉死）

### 1.1 霍尔 = 清零 / latch（稀疏绝对）

| 边沿 | 动作 |
|------|------|
| **GPIO4**（下扑） | `disc_ref ← 0°`，同时记下 `motor_counts_at_hall`（及展开角） |
| **GPIO5**（上举） | `disc_ref ← 180°`，同样 latch 电机计数 |
| `HALL CAL` | 把**当前姿**标为物理 0°（须在 GPIO4 点执行） |

用户表述：「霍尔经过相当于清零，然后根据电机当前位置，需要选择多少圈；磁编码器需要 **27 圈多**正好对应霍尔的位置。」

### 1.2 霍尔之后：只靠电机磁编连续推算

```text
gear = (59/12)×(79/14) = 4661/168 ≈ 27.7440476
     （小齿 12·14 / 大齿 59·79；一盘转 ≈ 27.744 电机转）

Δmotor_revs = esc_sense · (motor_counts − motor_counts_at_hall) / CPR
Δdisc_deg   = Δmotor_revs / gear × 360°
disc_phase  = wrap360(disc_ref + Δdisc_deg + PHASE_OFFSET)
```

| 符号 | 含义 |
|------|------|
| `CPR` | AS5047P = 16384 |
| `esc_sense` | ±1，使盘角随油门驱动方向递增 |
| `PHASE_OFFSET`（NVS `hphoff`） | 修固件 0 ↔ 物理 0/180 装反或标反；**选圈正确 ≠ OFFSET 正确** |

### 1.3 「选圈」（单向前向）

从当前盘相位到目标霍尔对齐相位，选 **电机转数**（整数+小数）：

```text
Δdisc_fwd = wrap360(target − disc)     // 沿 esc_sense 前进，最短前向弧（0..360）
motor_revs = gear × (Δdisc_fwd / 360)  // ≈ 27.744 × (Δdisc_fwd/360)

若制动距离不够（remain 对应电机转数 < 所需滑行/软降距离）：
  motor_revs += k × gear               // +k 整盘圈 = +k×27.744 电机转
```

**实现要点（软件）**：

- 剩余与 lead 的比较应能落到 **电机 counts/revs**（经 `gear`），避免「只比盘角、却用错零点/符号」的漂移捷径。  
- 现状固件：`discEstFromMotor()` + `discRemainFwd()` 已按 `Δmotor/gear`；lead 比较仍在**盘角域**（与 `gear` 成比例，数学等价，但「选圈」未单独成函数/日志字段）。  
- **缺口**：显式 `selectMotorRevsFwd(disc, target, min_revs)`、HOLD ACK/BRAKE 打一行 `motor_revs / counts_to_target`。

## 2. 控制架构

### 2.1 两段式（策略对比日志已验证方向）

```text
(A) 进场 / 软降（随起始 RPM 变长）
      当前高转速 → 捕获带（低 RPM + remain 进入窗）
(B) 终端不变式（与入口 RPM 无关）
      PHASE LEAD + crawl/HOLD → early-brake → SETTLE
```

任意转速停相位：**共用同一终端**；高速只是更长的进场。`hold_phase_strategy_cmp_*` 结论即此。

### 2.2 固件状态机（`HOLD PHASE`）

| 状态 | 行为 |
|------|------|
| `APPROACH` | 可选闭环软降（`stop_ms>0`）→ 开环爬行；**禁止**等霍尔才切油 |
| `BRAKE` | `remain ≤ lead_eff`（或霍尔已到而尚未 lead → `hall_*_before_lead`）→ PWM=1000µs |
| `SETTLE` | 等低转速；带内且（非霍尔目标 / 已 confirm / refine 关）→ `DONE`；否则见 REFINE |
| `REFINE` | 仅目标 **0°/180°** 且 `PHASE REFINE ON`：极低速爬至 GPIO4/GPIO5 沿 → 立刻停 → `DONE refine_hall` |

有效提前量（盘°，再经 gear 可换成电机转）：

```text
lead_eff = lead_deg + ω_disc×(lead_ms/1000) + k×|rpm_motor|
remain   = wrap360(target − disc)
切油条件: remain ≤ lead_eff     // 等价: motor_remain ≤ gear×lead_eff/360
```

**首次接近禁止**：等霍尔沿再停（惯量必冲过）。霍尔角色 = latch 绝对相 + 到位确认/诊断。  
**二次对准允许**：首停 `|err|>tol` 或无 `hall_confirm` 时，REFINE 极低速等到目标霍尔（默认 `tol=5°`，`max_disc≈370°`）。  
**90°**：无专用霍尔，跳过 REFINE（enc-only）。

### 2.3 架构锁（本工程）

| 层 | 频率 | 说明 |
|----|------|------|
| 采集 + 使用 | **2000 Hz** | SPI + 解缠 + 求速同层；禁「取用」 |
| 输出 | **400 Hz** | PID / ESC；实时路径零直打串口 |
| 数制 | **浮点主路** | `USE_FIXED_POINT` 默认 0；不因本功能切 Q16 |

## 3. 停位判定（软件能判定什么）

| 条件 | 软件能说什么 | 不能说什么 |
|------|----------------|------------|
| **已霍尔 latch**（`cal=1`） | `PHASE?` / `DONE disc` = 磁编相对最近 latch 的**估计盘相位** | 自动等于目视物理角（除非 OFFSET/接线已核对） |
| **判带** `[355,360)∪[0,5]` | 对固件 `disc` 做 wrap 带判定（建议独立函数 `inZeroBand(disc, tol=5)`） | 「物理一定在 0±5」 |
| **未 latch**（`cal=0`，`disc=-1`） | 只能报未标定 | **不能**声称绝对盘相位 |
| 固件 0 vs 目视 ~180/200 | 日志可提示「标架/OFFSET」 | 单靠选圈/lead 无法修好 |

**建议软件判据（验收）**：

```text
err = wrap180(disc − target)
pass_band = (|err| ≤ 5°)     // 目标 0 → disc ∈ [355,360)∪[0,5]
```

`DONE` 的 `hall_confirm`：首停过程中见过目标侧霍尔，**单独不足以**判物理到位（旧 miss 案例仍可 `hall_confirm=1` 且 `|err|≈170°`）。  
**已关闭的缺口**：首停 `|err|>tol` 或无 confirm 时进入 **REFINE**，爬到目标霍尔再停；`DONE reason=refine_hall` + `hall_confirm=1` 才把霍尔当作绝对对准。

## 4. 学习 / 「保证」停在 0° 或 355–5°

### 4.1 现有日志证据（无新硬件）

**Learn**（`hold_phase_learn_20260722_192921.txt`）：

| 项 | 值 |
|----|-----|
| 目标 / tol | `HOLD PHASE 0`，**tol=10°** |
| 迭代 | **1 / 4**（首轮已 PASS，未继续收紧） |
| 结果 | `disc≈355.5°`，`|err|≈4.5°`，`lead=10`，`offset=0` |
| NVS | `PHASE LEAD SAVE`（含 hphoff） |

→ 一次 learn **摸到**固件带内（且已 ≤5°），但 **tol=10 早停 ≠ 硬保证**；未做多转速回归。

**Strategy cmp**（`hold_phase_strategy_cmp_20260722_194014.txt`，共 12 次 HOLD DONE）：

| 落点（固件 disc） | 次数 | 说明 |
|-------------------|------|------|
| ∈ `[355,360)∪[0,5]`（|err|≤5） | **约 7** | 如 E、A_800、B、B2、C2、D_22、及部分 near-0 |
| 略出 5° 但仍近 0（约 349–351，|err|≈8–11） | **约 4** | A_2000、A_1000、D_18、D_28 |
| 明显 miss ~189° | **1** | `C_agg_soft200_hold0` |

→ **现状**：**偶尔 / 多数策略在固件盘相位近 0**；**不能保证**所有 RPM/策略都进 355–5；更 **不保证**目视物理 0。

### 4.2 「保证」在软件上要什么

1. **霍尔健康**（旋转时 GPIO4/5 有沿；否则无绝对 latch）。  
2. **标架正确**（GPIO4=物理 0、GPIO5=物理 180，或 `PHASE OFFSET` 已校准）。  
3. **NVS 持久 lead/offset**（`PHASE LEAD SAVE`）。  
4. **回归门闸**：多入口 RPM × 推荐终端配方，全部 `|err|≤5°`（固件盘）才标 PASS。  
5. Learn：**验收 tol=5°**，不够则改 lead/offset 继续迭代，禁止 tol=10 一次过就宣称保证。

### 4.3 软件计划（无硬件时仅设计）

| 步骤 | 内容 |
|------|------|
| Learn | 默认 `tol=5`；迭代调 `lead_deg/ms/k`；几何探针若「固件 0 后很快 GPIO5」→ `OFFSET += 180` |
| 回归套件 | 入口 2k/4k/6k × 终端（如 soft 800–1500 + lead≈10–22）；统计 band 命中率 |
| 拒收 | 任何 `disc≈180±30` 且 target=0 → FAIL + 标架告警，不记「停 0 成功」 |

**诚实结论**：当前 **不能**声称「已学习优化到保证停 0 / 355–5」。现状 = **固件盘相位多数近 0、learn 一次达标 tol=10；策略 C 可 miss 到 ~189°；物理对齐另论 OFFSET。**

## 5. API 与模块

### 5.1 串口（固件）

| 命令 | 作用 |
|------|------|
| `HALL?` / `HALL CAL` | 状态 / 强制 0° latch |
| `PHASE?` | `disc_deg`、`state`、`err`、`tol`、`hall_confirm`、`refine`、hold 状态 |
| `PHASE LEAD …` / `SAVE` | 提前量 + 可选写 NVS |
| `PHASE OFFSET …` / `SAVE` | 标架偏置 |
| `PHASE REFINE ON\|OFF\|?` | 0/180 首停后霍尔二次对准（默认 ON） |
| `PHASE TOL <deg>\|?` | 带判定容差（默认 5°，RAM） |
| `HOLD PHASE <deg> [crawl] [stop_ms]` | 盘相位保持；`PHASE 0|90|180` 简写 |
| `HOST OFF` | 台架禁主机超时 ESTOP |

### 5.2 固件模块（`firmware/ESP32ReadAS5047P`）

- `discLatchHall` / `discEstFromMotor` / `discRemainFwd`
