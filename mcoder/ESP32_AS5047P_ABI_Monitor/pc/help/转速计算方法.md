# AS5047P ABI 转速计算方法（PC / 手机）

固件：`FW=monitor-v40-counts-bin`  
BIN：`magic = 0xAB1C0002`（每点 16 字节）

---

## 1. 板端存什么（不存最终转速）

约 **2 kHz** 定时读一次 PCNT 累计值，写入一点：

| 字段 | 含义 |
|------|------|
| `t_us` | 相对本段起点的时间（微秒） |
| `counts` | ABI 正交解码后的累计步数（可正可负） |
| `index_n` | I 脉冲累计圈数相关计数 |

**边沿不会丢**：A/B 边沿由硬件 PCNT 连续计数；2 kHz 只是快照 `counts`，不是 2 kHz 才采一次边沿。

一圈步数默认 **`steps = 4000`**（AS5047P 十进制 ABI：**1000 PPR × 4** 正交）。若芯片烧成二进制 1024 PPR，则为 4096，需与固件/上位机一致。

ESP32 **本地**仍用短窗差分 + EMA 算 live RPM（监视与将来电机控制）；**记录文件里的转速不由板端定死**。

---

## 2. PC / 手机如何从 counts 算 RPM（蓝线「原始」）

对第 `i` 个点，默认向前跨 **`HOST_VEL_WIN = 32` 个采样点**（@2 kHz ≈ **16 ms**）：

\[
\mathrm{rpm}_i = \frac{\Delta c}{steps} \times \frac{10^{6}}{\Delta t} \times 60
\]

其中：

- \(\Delta c = counts_i - counts_j\)，\(j = \max(0,\, i - 32)\)
- \(\Delta t = t\_us_i - t\_us_j\)（微秒；\(\Delta t\le 0\) 时沿用上一有效值）
- 前几个点窗口不足时相对第 0 点；\(i=j\) 时 rpm=0

**此步不做 EMA。** 得到的序列即曲线工作室里的 **蓝线（rpm_raw）**。

旧文件 `magic = 0xAB1C0001`（12 字节含板端 `rpm_x10`）仍可读，直接用文件内转速，不再重算。

---

## 3. 橙线是什么

橙线 = 在蓝线之上，用曲线工作室里选的 **平滑方法**（滑动均值 / SG / EMA / IIR 等）再算一遍，用于观看与导出「平滑转速」。  
平滑窗、圈毛刺（排除点）**不改 BIN 里的 counts**；只有「固化排除」才会改表内数值。

---

## 4. 和旧方法的差别

| | 旧（板端写 rpm） | 现（v40 counts） |
|--|------------------|------------------|
| BIN | 每点瞬时 RPM | 每点 counts + 时间 |
| 差分 | 常为 1 个采样周期 → 低速台阶毛刺大 | 默认 32 点差分 |
| 改算法 | 须重烧固件并重采 | 可改窗长后对同一 BIN 重算 |
| 板端 live | 有 | 仍有（控制用） |

---

## 5. 采样率与记录时长（经验）

- **2 kHz**：弹射/短时转速曲线足够；中高速（如 1k～10k RPM）每个采样点有很多 counts，不会「同一位置采 5 点」。
- 「连续几点 counts 不变」只出现在**很低速**（半步都没走过），属正常，不是丢脉冲。
- 默认正式段约 **1 s**（可用串口/`REC MS` 改）；弹射过程多在 0.2～0.5 s。

---

## 6. 导出 CSV 常见列

- `t_rel_s`：相对时间（秒）
- `rpm_raw`：上文 §2 的差分转速（蓝线）
- `rpm_smooth`：§3 平滑后（橙线）
- 可选 `excluded`：圈毛刺排除标记
