# 总结报告：为何现在能正确记录并蓝牙下载

日期：2026-07-25（上午定稿记录链路；**下午补强手机 BLE，见文末 §8**）  
工程：`ESP32_AS5047P_ABI_Monitor`  
当前固件：**`FW=monitor-v37-keep-shot`**（上午可用基线曾为 `v26-ble-ram`）  
当前手机：**APK `1.9.4-share-csv`**  
当前 PC：源码 `pc/abi_monitor.py` 或单文件 **`AbiRpmMonitor-PC.exe`**

---

## 1. 一句话结论

**昨天弄不好**，主要不是「蓝牙协议写不出来」，而是：**触发确认后正式段写点路径被掐断 / 误入旧 STAGING**，再叠加 **BLE 遥测灌包 + SD/MSC 争用**，导致断链或拉不到完整 bin。

**现在能用**，是因为把链路定成：

```text
2 kHz 原始写入 INTERNAL RAM
  → SD 只做存档
  → BLE 从 RAM 拉同份数据（DUMP BIN BLE）；RAM 空则 SD 回退
```

并修掉了「CONFIRM 之后不再写 snap / 挤死 BLE」的关键逻辑错误。

**下午另加一层（手机特有）**：Android 主机行为不能照搬 PC 的持续 GATT READ；Dump 以 Notify+ACK 为主；武装后停实时流；弹射 keep-shot；分享走公共 Download CSV。详见  
`docs/工作日志与总结-2026-07-25下午-手机BLE.md`。

## 2. 昨天一直弄不好：现象与根因

### 2.1 典型现象（联调时）

| 现象 | 大致卡点 |
|------|----------|
| BLE 能扫到 / 能连，一进 STAGING/CONFIRM 就断 | 主机侧吞吐或栈被占满 |
| 触发了，正式段点数不对 / 几乎不写 | 写点分支走错 |
| USB 文本大包 DUMP 易复位 | CDC 灌包 + 大缓冲争用（旧路径） |
| 想从 SD 边读边 BLE 传 | SPI/FatFS 与 BLE 长传抢资源 |

### 2.2 关键根因：CONFIRM 后写点停了

设计意图：

1. `MONITOR START` 武装环缓  
2. `|RPM|>10` → STAGING  
3. **I 过 +1 圈** → 触发：回溯 ≤400 点 + 再记 **2 s @ 2 kHz** → RAM  
4. ALIVE → SD SAVE →（有 BLE 则）`BLE PULL READY` → `DUMP BIN BLE`

实际 bug（已在固件注释中标明）：

- 触发后 `snapIsArmed()` / 环缓武装标志被清掉；
- 定时采样路径**不再调用** `snapOnSampleCounts()`；
- 控制流落到**旧 STAGING / 旧 LOG 路径**；
- 正式段不写满，同时继续往 BLE 灌状态/遥测 → **Windows 上常见断链**。

修复要点（现行逻辑）：

```text
若 snapIsRecording() → 必须继续 snapOnSampleCounts，然后 goto 出口
不要在「已触发正式段」时再走旧 STAGING
STAGING/RECORD 期间 bleMuteHost(true)，降低遥测灌包
```

### 2.3 次要问题（也踩过）

| 问题 | 处理 |
|------|------|
| BLE 上电未自动开，PC 扫不到 | 改为上电自动 BLE / 或显式 `BLE ON` |
| SAVE 后自动 `USB DISK ON` | **有 BLE 连接时跳过 MSC**，避免占卡打断拉数 |
| 取数读 SD | 改为 **BLE 读 RAM**（与刚写入 SD 的点阵一致）；空则 SD 回退 |
| PC 误在 snap 完成时 `LOG DUMP` | 改为听 `BLE PULL READY` → `DUMP BIN BLE` |
| Android 与 PC 抢路径 | App 对齐：同样走 BIN BLE，跳过错误 LOG DUMP |

## 3. 现在正确工作的完整链路

```text
┌──────────── ESP32（2 kHz 采样保持）────────────┐
│ 武装环缓 → STAGING → 触发（含短弹射/掉速保留）  │
│ → 正式段按 REC MS 写入 INTERNAL RAM            │
│ → ALIVE → SD SAVE（/snap_*.bin 存档）          │
│ → 若 BLE 已连接：发 BLE PULL READY             │
│ → DUMP BIN BLE：HEX+ACK；优先 RAM，空则 SD     │
└───────────────────────────────────────────────┘
                    ↓
     PC（AbiRpmMonitor-PC.exe / abi_monitor --ble）
     手机 App 1.9.4（Notify 为主 Dump）
                    ↓
              曲线工作室离线分析
     （平滑 / 启动门控 / S·a，不改板内原始）
```

### 与「昨天」对照

| 维度 | 昨天（失败路径） | 现在（可用路径） |
|------|------------------|------------------|
| 正式段写点 | CONFIRM 后常写不完整 | `snapIsRecording()` 优先写满 |
| BLE 负载 | 触发后仍大量遥测/状态 | STAGING/RECORD 静音；武装后停 BLE 实时 L |
| 取数来源 | 易走 SD / 文本 LOG | **RAM 二进制**；空则 SD 回退 |
| SAVE 后 | 易自动 USB MSC | 有 BLE 则跳过 MSC，发 PULL READY |
| 客户端 | LOG DUMP 与 BIN 混用 | 统一 BIN BLE + ACK；手机勿狂 READ |
| 采样率 | 曾纠结降采样滤波 | **保持 2 kHz 原始**；平滑在 PC |

## 4. 刻意没做的事（避免再踩坑）

1. **不在板内对 snap 做强滤波 / 丢前 0.2 s**  
   原始 2 kHz 留给分析；启动脏段、Hampel、rate-clamp 在 **PC 曲线工作室** 做。

2. **不在 BLE 长传时边读边传 SD**  
   SD 只存档；拉数优先 RAM；空时先整文件载入再 BLE。

3. **不把「实时控速 400 Hz 滤波」混进记录通道**  
   那是另一类需求；混进 snap 会毁掉原始波形。

4. **不把 PC bleak 的持续 READ 原样搬到 Android**（下午教训）。

## 6. 验证清单（回归时用）

1. 烧录 v37 → `FW?` 确认版本  
2. PC：双击 `AbiRpmMonitor-PC.exe` 或 `python abi_monitor.py --ble` 扫到 `OEZ-ABI`  
3. 开始监控 → 转轴/弹射触发 → STAGING → CONFIRM/RECORD → **BLE 不断**  
4. `BLE PULL READY` → `DUMP BIN BLE` 收齐（`got≈exp`，非 2×）  
5. 手机：Notify Dump、分享 CSV、打开 `下载/AbiRpmMonitor`  
6. 曲线工作室：点数约 2 kHz × 时长，可再做启动裁切与平滑

## 7. 总结表

| 问题本质 | 昨天 | 现在 |
|----------|------|------|
| 记录 | 触发后写点路径错误 | RAM 正式段写满；短弹射 keep-shot |
| 蓝牙 | 灌包 + 错误分支 → 断链 | 静音 + RAM/SD 拉数；手机 Notify 为主 |
| 落盘 | 与取数耦合混乱 | SD 存档，BLE 优先读 RAM |
| 分析 | 缺离线工具 | PC 工作室（平滑/门控/S·a）+ exe 打包 |

**核心差异一句话：**  
昨天是「触发后逻辑跑偏 + 取数路径与 BLE 争用」；现在是「正式段必须继续写 RAM，BLE 只拉这份（或 SD 副本），SD 只备份；手机 Dump 不照搬 PC 狂读」。

## 8. 下午补充：手机 BLE 折腾摘要（2026-07-25 下午～晚）

上午把 **板内记录 + PC BLE** 打通后，下午主战场是 **手机 App**：

| 坑 | 后果 | 定稿对策 |
|----|------|----------|
| 照搬 PC 持续 GATT READ | 重复 `B,seq` → CRC 失败 | Dump Notify 为主；500ms 才救援 READ |
| 武装后仍读遥测 / PING | 断链、扰采样 | 流分离；静音期禁 READ/PING |
| 二次 MONITOR START | RAM 空、SD 仍有 | count 日志；禁二次武装；`SNAP?`→SD |
| 15s 猜结束 | 拉早/撞窗口 | 只认 `# BLE PULL READY` +200ms |
| STAGING 掉速回 IDLE | 0.3s 弹射丢数 | v37 keep-shot：掉速也触发记满 |
| FileProvider 路径错 | 分享即崩 | 导出 `Download/AbiRpmMonitor`；只发 CSV |
