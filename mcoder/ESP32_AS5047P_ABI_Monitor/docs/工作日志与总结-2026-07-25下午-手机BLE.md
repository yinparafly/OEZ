## 1. 一句话结论

手机问题的主因不是「蓝牙协议写不出来」，而是：

1. **把 Windows/PC（bleak）的主机行为原样照搬到 Android**（尤其持续 GATT READ）；  
2. **记录窗口与实时遥测/命令风暴争用同一条 BLE**；  
3. **二次 `MONITOR START` 清空 RAM**，表现为「RAM 空但 SD 有数据」；  
4. 弹射仅约 **0.3s**，旧触发逻辑在掉转速时容易 **回 IDLE 丢弃**，与业务不符。

正确方向：**空闲发实时转速；一武装就停发实时流；Dump 以 Notify + ACK 为主；RAM 优先、SD 回退；触发后记满既定窗口不因停转丢数。**

### 蓝牙折腾过程（叙述版）

下午核心矛盾是 **「PC 能用、手机不行」**，走过一条弯路：

1. **先怀疑手机太吵**：武装后仍 GATT READ / PING，遥测一停就狂读 → 断链或空 RAM。减命令后略好，但未根治。  
2. **再对齐 PC**：改掉错误的 15s 倒计时，只认 `# BLE PULL READY` + ~200ms；又发现 PC dump 时其实在轮询 READ，于是一度把「持续 READ」搬到 Android。  
3. **能下数了但 CRC 挂**：`got >> bytes=`。根因是 Android 上 Notify 后再 READ 同一 TX，常读到 **同一包缓存**，两路都 ingest。  
4. **请教两位朋友后纠偏**：Android ≠ Windows；Dump **以 Notify 为主**，超时才救援 READ；禁止 HIGH priority / 自动重连。落地 v36 / 1.9.0。  
5. **产品侧补齐**：流分离（v35）、SD 回退、`SNAP? valid=`、禁止二次武装清 RAM、弹射 keep-shot（v37）、分享目录修复与 CSV-only（1.9.3～1.9.4）。

弯路教训写进 §5；上午「记录写点 + RAM 拉数」见 `总结报告-记录与蓝牙为何可用-2026-07-25.md`。

## 3. 根因清单（按优先级）

### 3.1 Android GATT：Notify 后再 READ 易重复

- 特征值 value 是共享缓冲；`readCharacteristic(TX)` 常返回 **上一次 Notify 的同一内容**。  
- 两路都 `ingest` → 每个 `B,seq,hex` 写两遍 → `got >> bytes=` → **CRC 失败**。  
- PC（Windows+bleak）也有此现象，但 PC 用 `last_val` 去重；手机一度「照搬狂读」却去重不够，问题被放大。

**对策**：Dump 期间默认 **不 READ**；仅 500ms 无新包才救援 READ；`lastIngestPayload` + `B,seq` 去重；超 `bytes=` 截断。

### 3.2 记录窗口灌包 / 主机干扰

- 板子 STAGING/RECORD 已 `bleMuteHost`，停发实时 `L`。  
- 手机旧逻辑：遥测一停就 GATT READ + PING → 断链或采样受扰。  

**对策**：流分离；武装期间手机也不轮询读；无 PING；无 `CONNECTION_PRIORITY_HIGH`；无自动重连。

### 3.3 RAM 空但能下到数据

- 固件：**仅 `MONITOR START` → `snapArmBegin()` 清空上一拍 RAM**。  
- SD 在 SAVE 时已有副本 → 可 `DUMP BIN BLE SD` / 自动回退。  
- 常见误操作：记完后再点「开始监控」或重连后误武装。  

**对策**：`# MONITOR START count=N`；拉数/武装中禁用「开始监控」；拉前 `SNAP?`（`valid=0` 走 SD）。

### 3.4 拉数时机

- PC：只认 `# BLE PULL READY` → **~200ms** → `SNAP?` → `DUMP BIN BLE`。  
- 手机曾用 15s 倒计时、多事件源乱开拉 → 窗口内易二次武装/断线。  

**对策**：与 PC 相同触发源与延迟。

### 3.5 弹射仅 ~0.3s

- 旧 snap 路径：STAGING 中 RPM 掉到门限一半 → **回 IDLE**，短弹射易丢。  
- 用户规则：一旦进入记录流程，**既定时长内数据全部保留**，停转也继续采。  

**对策（v37）**：STAGING 掉速不丢弃，改为尽快 `snapTriggerFromRing`；正式段按 `REC MS` 记满（RPM=0 也写点）。

### 3.6 分享崩溃 / 打不开文件夹（傍晚）

- 导出写在 `…/files/Documents/exports`，FileProvider 只允许 `exports/` → `getUriForFile` 抛异常 → 应用退出。  
- 「打开文件夹」只 toast 路径 / 打开说明 txt，没有进真实目录。  

**对策**：导出到公共 **`Download/AbiRpmMonitor`**；DocumentsUI / 下载管理器打开；分享只发 CSV。

## 4. 最终数据链路（当日定稿）

```text
未武装：BLE 发短帧 L（实时转速）
    │
    ▼ MONITOR START（清上一拍 RAM；发 count；BLE 停 L）
环缓 + |RPM|>门限 → STAGING
    │  （掉速也不丢：短时/环缓/I+1/掉速挽救 → 触发）
    ▼ snapTriggerFromRing + 正式段记满 REC 时长
INTERNAL RAM 满 → ALIVE → SD SAVE /snap_*.bin
    │
    ▼ # BLE PULL READY
手机：SNAP? → valid=1 DUMP BIN BLE(RAM) / valid=0 DUMP BIN BLE SD
    │  Notify + DUMP ACK；禁止狂 READ
    ▼ CRC OK → 曲线 → 自动导出 CSV（+本地 PNG 可选）
         →「发送数据」只发 CSV；「打开文件夹」→ 下载/AbiRpmMonitor
```

协议要点：

```text
# BIN BLE BEGIN src=RAM|SD n=… bytes=… crc=0x…
B,<seq>,<hex>
# BIN BLE END …
主机每行：DUMP ACK（兼容 ACK,）
```

## 5. 手机蓝牙设计规则（后续项目请遵守）

### 5.1 流与阶段

| 阶段 | 板子 BLE | 手机主机 |
|------|----------|----------|
| 空闲未武装 | 可发实时 `L` | Notify 为主；READ ≥200ms 兜底；禁止 PING |
| 武装～记录 | **禁止**实时 `L`；只发短事件 | **禁止** READ/PING/DIAG；只听事件 |
| DUMP BIN | 分包 + 等 ACK | **Notify 为主**；超时才救援 READ；立即 ACK |
| 断线 | 保留 RAM（除非再 MONITOR START） | **禁止自动重连**；用户手动连 |

### 5.2 绝对不要做的事（Android）

1. Dump 时 **40ms 级持续 `readCharacteristic`**（Windows 补洞方案，手机上易重复包）。  
2. `CONNECTION_PRIORITY_HIGH` 贯穿全程（记录窗口与 2kHz 采样争用）。  
3. 掉线自动重连撞 STAGING/RECORD/SAVE。  
4. 记完/拉数过程中再发 `MONITOR START`（清 RAM）。  
5. 用 15s 倒计时或手机「猜」记录是否结束；只认板子 `# BLE PULL READY`。  
6. 在 `onCharacteristicChanged` 里延迟读 `getValue()` 而不拷贝（缓冲会被覆盖）。  
7. FileProvider paths 与真实导出目录不一致（分享必崩）。

### 5.3 必须做的事

1. 所有 GATT 操作（READ/WRITE/CCCD）**串行队列**，等回调再下一个。  
2. Notify/Read 回调里 **立刻 `Arrays.copyOf`**。  
3. BIN 收包：`payload` 去重 + `B,seq` 去重；超 `bytes=` 截断再 CRC。  
4. 拉数前 `SNAP?` → `# SNAP valid=0|1` 决定 RAM / SD。  
5. 写命令：`WRITE_TYPE_NO_RESPONSE`（对齐 PC）；引导精简：`TIME` / `BLE RATE` / `ABI?`，武装仅 `TIME`→40ms→`MONITOR START`。  
6. 产品路径：**RAM 快路径 + SD 可靠回退**；接受 `src=SD`。  
7. 分享只发 **CSV 数据包**；导出目录对用户可见（公共 Download）。

### 5.4 业务记录规则（弹射类）

1. 触发条件可松（短窗 0.2s / 环缓 / I+1 / **掉速挽救触发**）。  
2. **一旦触发**：按 `REC MS` 记满整窗，**停转不丢、不提前结束采样**。  
3. 只有用户再次 `MONITOR START` 才允许清上一拍 RAM。  
4. SD 存档与 BLE 拉数解耦：先存卡，再传；传时优先读 RAM，空则读卡文件到内存再 BLE（避免边传边 SPI）。

### 5.5 联调检查清单

1. 串口是否出现：`# QUIET` → `# CONFIRM` → `# RECORD done` / `# CD15` → `# BLE PULL READY`  
2. `# MONITOR START count=` 是否异常连涨  
3. `# SNAP valid=` 与 `# BIN BLE BEGIN src=`  
4. 进度是否 `got ≈ exp`（若 `got≈2×exp` → 又在重复收包）  
5. 仅手机 vs 仅 PC 对比触发是否发生
