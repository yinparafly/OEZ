## 1. 这个项目是干什么的

面向 **弹射 / 短时转速** 场景：ESP32-S3 读 AS5047P（ABI），在触发后以约 **2 kHz** 把转速点写入 **INTERNAL RAM**，再 **SD 存档**；PC 或手机通过 **蓝牙（NUS）** 或 USB 把二进制拉回，在 **曲线工作室** 里做平滑、圈毛刺、导出。

一句话链路：

```text
武装 MONITOR → 触发 → RAM 记满 → SD /snap_*.bin
       → BLE PULL READY → DUMP BIN BLE（优先 RAM，空则 SD）
       → PC/手机曲线 → 平滑/排除毛刺 → 导出 CSV
```

## 3. 系统架构

```text
                    ┌─────────────────────────────┐
                    │  AS5047P (A/B/I ABI)        │
                    │  A=GPIO15 B=16 I=17         │
                    └─────────────┬───────────────┘
                                  │ PCNT + 2kHz 采样
                    ┌─────────────▼───────────────┐
                    │  ESP32-S3                   │
                    │  snap RAM → SD /snap_*.bin  │
                    │  BLE NUS「OEZ-ABI」         │
                    │  USB CDC + 可选 MSC U盘     │
                    └───────┬───────────┬─────────┘
               DUMP BIN BLE │           │ DUMP BIN / 串口
              ┌─────────────▼──┐   ┌────▼──────────────┐
              │ Android App    │   │ PC abi_monitor    │
              │ BleClient      │   │ ble_link / serial │
              │ 曲线 + 分享CSV │   │ curve_studio      │
              └────────────────┘   └───────────────────┘
```

### 3.1 固件状态（简化）

1. **空闲**：可发短帧实时 `L,...`（BLE）；USB 可一直有遥测。  
2. **MONITOR START**：清上一拍 RAM（注意！）、停 BLE 实时 L、开环缓。  
3. **STAGING**：转速过门限；短弹射 keep-shot：掉速也尽量触发，不轻易回 IDLE。  
4. **RECORD**：按 `REC MS` 记满（停转也继续写点）。  
5. **ALIVE → SD SAVE** → 有 BLE 则 `# BLE PULL READY`（跳过 MSC）。  
6. **DUMP BIN BLE**：`src=RAM` 优先；空则载入最新 SD 再 HEX 分包 + 等 `DUMP ACK`。

### 3.2 主机侧差异（接手必守）

| | PC (bleak) | Android |
|--|------------|---------|
| Dump | Notify + 可辅 READ + last_val 去重 | **Notify 为主**；~500ms 无包才救援 READ |
| 武装期 | 少命令 | **禁止** READ/PING/HIGH priority/自动重连 |
| 拉数时机 | 只认 `# BLE PULL READY` + ~200ms | 同左；勿 15s 猜结束 |
| 二次武装 | 会清 RAM | 拉数中禁用「开始监控」 |

详规见：`docs/工作日志与总结-2026-07-25下午-手机BLE.md` §5。

### 3.3 数据格式（snap BIN）

- 点：12 B：`t_us u32, rpm_x10 i16, dir i8, pad u8, index_n u32`  
- USB DUMP：magic `0xAB1C0001` + n + hz + 点阵 + CRC32  
- BLE：文本行 `# BIN BLE BEGIN ...` + `B,<seq>,<hex>` + END；主机每行 `DUMP ACK`

## 4. 硬件接线（摘要）

| AS5047P | ESP32-S3 |
|---------|----------|
| A / B / I | GPIO15 / 16 / 17 |
| VCC / GND | 3.3V / GND |

SPI SD：`CS=10, SCK=12, MOSI=11, MISO=13`  
串口调试常见：CH343 → **COM6**（以本机为准）。  
BLE 名：`OEZ-ABI`。同一时间 **PC 与手机不要同时占 BLE**。

## 5. 关键指令与联调最短路径

| 指令 | 作用 |
|------|------|
| `MONITOR START` / `STOP` | 武装 / 解除 |
| `REC MS <ms>` | 正式段时长 |
| `TIME <unix_ms>` | 对时 |
| `SNAP?` | `# SNAP … valid=0\|1` |
| `DUMP BIN BLE` / `DUMP BIN` | 蓝牙 / USB 拉二进制 |
| `SD SAVE` | RAM→卡 |
| `USB DISK ON` | 只读 U 盘 |
| `FW?` | 查固件标识 |

回归：

1. `flash_com6.bat` → 串口见 `FW=monitor-v38-vel-win`（回退：`backups/v37-keep-shot-2026-07-26/`）  
2. PC `--ble` 或 exe → 扫 `OEZ-ABI` → 开始监控 → 转轴/弹射  
3. 见 `BLE PULL READY` → 自动拉齐（`got≈exp`，不是约 2×）  
4. 打开曲线工作室 → 平滑 / 圈毛刺 → 导出 CSV  
5. 手机：同流程；导出在 **下载/AbiRpmMonitor**；分享只发 CSV

## 6. 曲线工作室（PC）能力摘要

- **Cut / 选择 / 圈毛刺**：圈毛刺 = 排除点（红叉），不改原始表；可「固化排除→邻点」才改数值。  
- **平滑参数**：改方法/窗/σ 等 **自动重绘**（约 200ms 防抖）。  
- **导出重算曲线**：同一 `t_rel_s`（X）+ `rpm_raw`（Y1）+ `rpm_smooth`（Y2）。

源码：`pc/curve_studio.py`、`pc/rpm_chart.py`、`pc/snap_edit.py`。

## 8. 已知坑与口令（给接手人）

1. **再次 MONITOR START 会清 RAM** → 表现为「RAM 空、SD 有」；拉前看 `SNAP? valid=`。  
2. **Android 不要照搬 PC 持续 GATT READ** → 重复包 CRC 失败。  
3. **分享 FileProvider 路径必须与真实导出目录一致** → 现用公共 `Download/AbiRpmMonitor`。  
4. **短弹射 ~0.3s**：固件 v37 keep-shot，触发后记满窗口，停转不丢。  
5. 烧录前关掉占用串口的 `abi_monitor` / exe。  
6. exe 被占用时覆盖失败 → 用 `AbiRpmMonitor-PC-new.exe`。

口令：

> Android ≠ Windows BLE。一监控就静音；一 Dump 就 Notify+ACK。RAM 优先，SD 保底。弹射记满窗。
