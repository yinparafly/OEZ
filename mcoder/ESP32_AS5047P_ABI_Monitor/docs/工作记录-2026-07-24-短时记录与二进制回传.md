## 1. 目的

用户真实需求很简单：

1. **电机可以先转起来**；
2. **点一下**开始采约 **1 秒**原始转速；
3. 数据完整到 PC，**落盘、可分析**；
4. **不要**门限 / 确认 / STAGING / 噪声丢弃那套“弹射逻辑”挡在主路径上；
5. **0 RPM 也是有效数据**；“没数据”= **0 个采样点**（回传/复位问题），不是“转速为 0”。

技术目标：

- 采样：**2 kHz × 1 s ≈ 2000 点**；
- 板内能记满 ≈2000 点；
- PC 落盘点数应接近板内 `n`，而不是几十点残片。

---

## 2. 方法（当天演进与最终方案）

### 2.1 问题定性（朋友诊断 + 本机证据）

- 板内多次出现 `log_n≈2000` / 后来 `SNAP DONE n≈2000` → **PCNT + 写 RAM 基本通**；
- PC 常只拿到几十点；RECORD/DUMP 后出现开机横幅 → **复位清 RAM**；
- 根因判断：**不在计数，而在 USB 文本回传 + 复位 + 主机过早收尾**。

### 2.2 最终采用架构（最小可行记录仪）

```
PC: REC / REC NOW
  → 板: 2kHz 定时器，仅整数读 PCNT、推内部 RAM（禁止 ISR 内 float/Serial）
  → 满 1s: 只打一行 # SNAP DONE n=…
PC: DUMP BIN（停定时器）
  → 板: magic(4) + n(2) + hz(2) + n×12 + CRC32(4) 纯二进制写出
PC: 流内搜 magic → 定长收齐 → CRC 校验 → CSV
```

| 项 | 做法 |
|----|------|
| 记录缓冲 | 内部 RAM，`snap_bin`，约 3000×12 B |
| ISR | 整数 `delta` → `rpm_x10`，无浮点 |
| 回传 | 二进制块 + CRC，不用 2000 行 `D,...` 文本 |
| 实时转速 | 仍可用文本 `L,`；与 SNAP 回传通道分离 |
| 旧路径 | `MONITOR` / `LOG DUMP` 文本仍保留作对照，短时 1s **以 DUMP BIN 为准** |

## 3. 遇到的问题

| # | 现象 | 原因 / 处理 |
|---|------|-------------|
| 1 | 板上 `log_n≈2000`，PC CSV 只有几十点 | USB CDC 连续文本易丢包/复位；改为二进制 |
| 2 | DUMP 后再次出现 `# ESP32 … FW=…` 开机横幅 | 板子复位，RAM 日志被清空 |
| 3 | 门限/STAGING/freeze 导致“转了却不记” | 主路径改为 `REC NOW` 直采，旁路门限 |
| 4 | **`REC NOW` 被 `REC MS` 前缀误吞** | `REC ` 匹配进时长设置，`atoi("NOW")→500`，从未真正直采 → 已修 |
| 5 | PC `#` 行用 `append` 后接 `elif` | `SNAP DONE`/`RECORD done` 等状态分支常进不去 → 已改为先 append 再 `if` 链 |
| 6 | `BIN CRC mismatch expect=0x2C302C30`（ASCII `0,0,`） | 定长窗口尾部落进文本；BIN BEGIN+分块 `yield` 易夹脏 → **v18**：二进制前不打文本、禁止 yield；PC **magic 同步** |
| 7 | `# UI poll err: float - NoneType` | `_dump_watch_t0 = None` 后仍 `hasattr` 为真再做减法 → 改为 `is None`；等 BIN 时禁止改走文本 LOG DUMP 重试 |
| 8 | 烧录时 COM6 busy | UI 占用串口；需先关 `abi_monitor.py` 再 flash |

残片样例（改 BIN 前）：`pc/logs/20260724_190046/`（59 点）、`pc/logs/20260724_190928/`（9 点）。
