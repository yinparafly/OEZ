ArduPilot SITL 连接问题 — 完整测试总结与疑问
================================================
日期: 2026-07-05
环境: Windows 10 (19045) + WSL2 Ubuntu 22.04 + pymavlink 2.4.49

========================================
一、官方文档标准做法 (我们验证过的内容)
========================================

ArduPilot 官方文档 (使用SITL测试.html) 明确说明了两种连接方式:

1. TCP 模式 (默认):
   sim_vehicle.py --no-mavproxy
   → SITL 监听 TCP 5760, 等待 GCS 连接
   → GCS 用 TCP 连接到 SITL

2. UDP 模式:
   sim_vehicle.py -A "--serial0=udpclient:<gcs ip>:14550"
   → SITL 通过 UDP 发送数据到指定地址
   → GCS 监听 UDP 端口接收数据

3. MAVProxy 转发 (推荐):
   sim_vehicle.py (不加 --no-mavproxy)
   → MAVProxy 自动连接 SITL
   → 用 "output add <ip>:<port>" 转发到其他 GCS

========================================
三、关键发现
========================================

发现1: clock bits 不阻塞仿真
  来源: SIM_LP5562.cpp (LED 驱动仿真)
  只是 stderr 输出, 不影响主循环
  方案D(默认)没有此消息, 方案A/B/C有
  结论: clock bits 不是问题根因

发现2: TCP 从 Windows 到 WSL 全部失败
  tcp:127.0.0.1:5760         → ConnectionRefused
  tcp:172.30.31.168:5760     → ConnectionRefused (WSL IP)
  tcp:172.30.16.1:5760       → ConnectionRefused (Windows IP)
  原因: WSL2 NAT 模式下 TCP 端口不可达

发现3: UDP 能收到心跳但 System=0
  udp:127.0.0.1:5760         → 心跳OK, 0条数据
  udp:127.0.0.1:14550        → 心跳OK, 0条数据
  udp:0.0.0.0:14550          → 心跳OK, 0条数据
  request_data_stream_send 已调用但无响应

发现4: sim_vehicle.py --udp 的 --out 参数
  --out 参数只传给 MAVProxy, 不传给 arduplane
  arduplane 收到的命令行没有 --serial0 参数
  sim_vehicle.py --udp 设置 --serial0 udpclient:127.0.0.1:5760

发现5: mirrored 模式不支持 Windows 10
  需要 Windows 11 22H2+
  我们的系统是 Windows 10 (19045)

========================================
五、我们的环境特殊性
========================================

1. Windows 10 (不是 11) — 不支持 mirrored 模式
2. WSL2 NAT 模式 — TCP 端口不可达
3. Python 在 Windows 上运行 (不是 WSL 内)
4. pymavlink 2.4.49 (Windows Python 3.12)
5. ArduPilot 源码在 WSL 中编译
6. arduplane 二进制在 WSL 中运行

========================================
六、已排除的方案
========================================

1. mirrored 模式 — 需要 Windows 11
2. 直接用 udp: 前缀启动 arduplane — 源码不支持
3. udpout: 前缀 — 源码中不存在
4. 修改 .wslconfig 启用 localhostForwarding — 已配置但无效
5. WSL IP 直连 — TCP 仍被拒绝
