ArduPilot SITL 连接 — 最终总结与疑问
======================================
日期: 2026-07-05 01:30

========================================
一、我们验证了什么
========================================

严格按官方文档操作了以下步骤:

1. 官方标准 TCP 方式:
   sim_vehicle.py --no-mavproxy
   → arduplane 监听 TCP 5760, 等待 GCS 连接
   → 从 Windows pymavlink 连接 tcp:127.0.0.1:5760 → ConnectionRefused

2. 官方 UDP 方式:
   sim_vehicle.py -A "--serial0=udpclient:172.30.16.1:14550"
   → arduplane 发送 UDP 到 Windows IP
   → pymavlink 连接 udp:0.0.0.0:14550 → 收到心跳, System=0, 无数据

3. 官方带 MAVProxy 方式:
   sim_vehicle.py (不加 --no-mavproxy)
   → MAVProxy 连接 tcp:127.0.0.1:5760 (WSL 内部)
   → MAVProxy 等待心跳, 超时退出

4. 分开启动:
   先启动 arduplane (TCP 5760)
   再启动 mavproxy.py --master tcp:127.0.0.1:5760
   → MAVProxy 连接成功, 但收不到心跳, 退出

========================================
二、核心发现
========================================

发现1: arduplane 日志显示 "Connection on serial port 5760"
  说明 TCP 连接确实建立了
  但 MAVProxy 仍然收不到心跳
  原因: arduplane 卡在 "Waiting for internal clock bits to be set (current=0x00)"

发现2: "clock bits" 来自 SIM_LP5562.cpp (LED 驱动仿真)
  这个消息出现后, arduplane 不再响应 MAVLink 请求
  即使 TCP 连接建立, 也不会发送心跳
  这是仿真未初始化的标志

发现3: 为什么默认配置没有 clock bits?
  当不指定 --serial0 时, arduplane 使用默认 tcp:0:wait
  此时没有 clock bits 消息
  但指定 --serial0 后就出现
  可能与 serial 初始化顺序有关

发现4: WSL2 NAT 模式下
  TCP 从 Windows 到 WSL 全部失败 (ConnectionRefused)
  UDP 可以收到心跳但飞控未初始化
  Windows 10 不支持 mirrored 网络模式
